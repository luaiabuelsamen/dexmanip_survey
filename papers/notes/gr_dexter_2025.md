# gr_dexter_2025 — GR-Dexter Technical Report (Wen et al., ByteDance Seed, arXiv 2025/2026)

sources: papers/md/gr_dexter_2025.md [5ff86922 / arxiv 2512.24210] ; no code

## One-line contribution
A hardware-model-data framework — a compact 21-DoF ByteDexter V2 hand, a Meta-Quest+Manus-glove bimanual teleoperation rig, and a 4B-parameter Mixture-of-Transformer VLA (GR-Dexter, following GR-3) co-trained on teleoperated robot data, vision-language data, cross-embodiment robot datasets and human egocentric trajectories — for generalist manipulation on a 56-DoF bimanual dexterous-hand robot (Abstract, §1, §3).

## Setting
- hand(s): ByteDexter V2, 21 DoF per hand (4 DoF × 4 fingers + 5 DoF thumb), linkage-driven, multi-fingered, with piezoresistive tactile fingertip sensors; height 219 mm, width 108 mm (§2, §2.1). Arm: two Franka Research 3 (FR3) arms, 7 DoF each. Bimanual: yes, "bi-manual robot with fixed base" (§3) — fixed torso/base, not a mobile humanoid.
- simulator / physics: none — this is a real-robot-only system; no simulator is used for training or evaluation anywhere in the parsed text.
- observation: per §3, policy π_θ(a_t | l, o_t, s_t) conditions on language instruction l, visual observation o_t (four global RGB-D cameras: one primary egocentric + three third-person views, §2.2), and robot state s_t. Exact state-vector composition beyond this is not stated.
- action space: action a_t is an 88-dim vector per step, a k-length chunk a_t:t+k generated via flow matching: "1) arm joint actions (7 DoFs per arm), 2) arm end-effector poses (6D per arm), 3) hand joint actions (16 active DoFs per hand), and 4) fingertip positions (3D per finger)" (§3). Note: hand has 21 DoF total but only 16 are called "active" in the action vector.
- objects / data: ~20 hours of teleoperated trajectories for the makeup-decluttering long-horizon task (§4.1); ~20 hours of teleoperated trajectories with 20 training objects for pick-and-place (§4.2); cross-embodiment data from Fourier ActionNet (~140 h, Fourier 6-DoF hands), OpenLoong Baihu (>100k trajectories, multi-embodiment), RoboMIND (107k demonstrations, 479 tasks, 96 object classes) (§3.1); human trajectory data ">800 hours of egocentric video with paired 3D hand and finger tracking data" plus additional Pico VR data (§3.1).

## Method
- paradigm: VLA (Mixture-of-Transformer, flow-matching action expert + next-token-prediction VLM backbone), following GR-3; not RL, no simulation-based training.
- reward or loss (quoted): "The robot trajectory data are used to train both the VLM backbone and the action DiT using the flow-matching objective. ... The vision-language data are used to train only the VLM backbone via the next-token-prediction objective. ... the co-training objective is the sum of the next-token-prediction loss and the flow-matching loss" (§3.1). No explicit weighting between the two losses is given, and no code is available to check an implementation.
- key trick(s): fingertip-centric cross-embodiment retargeting ("aligning the fingertips... preserves task-relevant contact geometry while remaining agnostic to joint-level discrepancies", §3.2); masking unavailable/unreliable action dimensions to unify heterogeneous embodiments (§3.1); hand-motion teleoperation retargeting as constrained SQP optimization combining wrist-to-fingertip and thumb-to-fingertip alignment with collision-avoidance constraints and regularization (§2.2); parameterized trajectory optimizer smooths generated action chunks at rollout time, "critical for delicate grasping" and for smooth cross-chunk transitions (§2.2).

## Contact / penetration handling
Not addressed as a hand-object interpenetration metric or penalty anywhere in the paper. The only collision-related mechanism stated is in the teleoperation retargeting optimization, which includes "collision-avoidance constraints" as part of the SQP formulation mapping human wrist/hand motion to robot joint commands (§2.2) — this avoids the teleoperated robot self-colliding/penetrating during retargeting, not a measured or penalized hand-object penetration term for the learned policy.

## Coordination and embodiment (survey fields)
- two-hand coordination: one policy over both arms and both hands — a single VLA π_θ outputs the full 88-dim bimanual action chunk jointly (arm joints, EE poses, hand joints, fingertip positions for both sides at once, §3). No leader/follower role split or relative-frame two-hand observation is described; teleoperation likewise drives both arms/hands simultaneously from one operator via a "whole-body controller" (§2.2). Authors explicitly flag as a limitation that "the robot's hand and arm are controlled separately, which can hinder tight hand-arm coordination" (§6) — i.e., hand and arm control loops are decoupled even though one policy generates both outputs.
- torso: fixed base ("bi-manual robot with fixed base", §3) — two arms mounted on a stationary dual-arm platform, not a mobile humanoid.
- hand model/DoF each side: ByteDexter V2, 21 DoF per hand (16 "active" DoF used in the action vector), identical on both hands, multi-fingered (not a parallel-jaw gripper).

## Evaluation
- metrics (exact definitions): "average success rate across multiple evaluation trials" for long-horizon makeup decluttering (§4.1), evaluated over 6 sequential sub-task instructions per rollout; for pick-and-place, "A trial is considered successful if the robot picks up the target object and places it into the container" (§4.2).
- headline numbers: Makeup decluttering (Fig. 7) — Basic (in-domain layouts): plain VLA 0.96 vs GR-Dexter 0.97; OOD (5 unseen layouts, same instruction order): plain VLA drops to 0.64 vs GR-Dexter 0.89. Pick-and-place (Fig. 8) — Basic (10 eval batches × 5 seen objects = 50 trials, object layout fixed per batch across policies): plain VLA 0.87, GR-Dexter w/o cross-embodiment data 0.85, GR-Dexter 0.93; Unseen Objects (10 batches × 5 of 23 unseen objects = 50 trials): GR-Dexter reaches 0.85; Unseen Instructions (5 batches × 5 objects = 25 trials, seen+unseen objects with unseen instructions): GR-Dexter reaches 0.83 (exact plain-VLA/no-cross-embodiment numbers for these two OOD settings are described only qualitatively as "drops significantly" / "still suffer from inaccurate grasping", not given as numbers in the parsed text).
- baselines beaten: "plain VLA" (GR-Dexter architecture trained only on robot teleoperation data, no co-training) and an ablation "GR-Dexter w/o cross-embodiment data".
- real robot? Yes, exclusively — all numbers above are real-world trials on the two-FR3-arm + two-ByteDexter-V2-hand platform; no sim numbers reported anywhere.

## Limitations stated by the authors
"(1) on the human side, we leverage only a few hundred hours of human trajectories, leaving substantial complementary egocentric human data untapped; and (2) the robot's hand and arm are controlled separately, which can hinder tight hand-arm coordination in contact-rich dexterous behaviors" (§6).

## Quotable claims (verbatim, with section)
- "π_θ(a_t | l, o_t, s_t) controls a bi-manual robot with fixed base by generating a k-length action chunk ... each action a_t is a vector of length 88, consisting of: 1) arm joint actions (7 DoFs per arm), 2) arm end-effector poses (6D per arm), 3) hand joint actions (16 active DoFs per hand), and 4) fingertip positions (3D per finger)" (§3).
- "Hand-motion retargeting is formulated as a constrained optimization problem that combines wrist-to-fingertip and thumb-to-fingertip alignment terms with collision-avoidance constraints and regularization, and is solved using Sequential Quadratic Programming" (§2.2).
- "the robot's hand and arm are controlled separately, which can hinder tight hand–arm coordination in contact-rich dexterous behaviors" (§6).
