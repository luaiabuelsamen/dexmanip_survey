# anyrotate_2024 — AnyRotate: Gravity-Invariant In-Hand Object Rotation with Sim-to-Real Touch (Yang et al., CoRL 2024, arXiv 2405.07391)

sources: papers/md/anyrotate_2024.md [sha256 e5adc809] ; no code

## One-line contribution
A teacher-student RL policy trained in IsaacGym with a dense tactile representation (contact pose + contact force) and a goal-conditioned auxiliary-goal reward achieves multi-axis in-hand object rotation about an arbitrary axis in an arbitrary hand orientation relative to gravity, and transfers zero-shot to a real Allegro Hand via a learned tactile-perception model (Abstract; Sec 3).

## Setting
- hand(s): "16-DoF Allegro Hand" (Sec 4, System Setup), 4 fingers, vendor not stated beyond "Allegro Hand"; custom front-facing vision-based tactile sensors on each fingertip. arm: 6-DoF UR5 — "The hand is attached to the end effector of a UR5 to provide different hand orientations for performing in-hand object rotation" (Sec 4). single/bimanual: single hand-arm system.
- simulator / physics: IsaacGym [53] (Sec 4, Simulation); physics engine name not stated beyond "IsaacGym". Sim timestep dt = 1/60 s; policy control at 20 Hz (Sec 4). Parallel envs: Table 7 gives Num Envs = 8192 for both teacher and student training.
- observation: proprioception + dense tactile + task, itemized in Table 4 (see Learning block below); privileged info (teacher only) in Table 5.
- action space: relative joint position Δθ ∈ R^16, EMA-smoothed target, control at 20 Hz — see Learning block.
- objects / data: sim training on capsule and box primitives (Sec 4, Object Set); sim OOD test sets "OOD Mass" (heavier mass) and "OOD Shape" (unseen shapes) from [54] (Fig. 4); real world 10 everyday objects with dimensions/mass in Table 10 (Appendix J).

## Method
- paradigm: RL (teacher, privileged information) + supervised distillation (student). Algorithm: PPO [52] (Schulman et al.) implemented via rl-games [56] (Table 7 hyperparameters — Advantage Clip ε, GAE τ, KL Threshold, minibatch/epoch structure — match a PPO/rl-games setup); student training references RMA [57] for the TCN teacher-student recipe.
- reward or loss: see Reward block C below (quoted from Appendix B).
- key trick(s): (i) auxiliary-goal formulation — object rotation reframed as reorientation to a moving keypoint target generated by rotating the current object orientation about the desired axis at intervals, replacing an angular-velocity objective that the authors found unlearnable in the multi-axis setting (Sec 3.1, Sec 5.1); (ii) adaptive reward curriculum on the contact/stability terms, gated by rotations achieved (Sec 3.1, Appendix B.3); (iii) dense tactile feature (contact pose + contact force) simulated as a rigid-body contact probe and mapped to a learned CNN tactile-perception model for zero-shot real transfer (Sec 3.3).

## A. Embodiment block
- Hand: 16-DoF Allegro Hand, 4 fingers, vendor not stated. Arm: UR5, 6-DoF. **Hand is arm-mounted, not fixed**: "The hand is attached to the end effector of a UR5 to provide different hand orientations" (Sec 4, System Setup) — the arm is used specifically to realize different hand orientations relative to gravity, and (Appendix K.4) to continuously rotate the hand during a rollout. Bimanual: no.
- Simulator: IsaacGym [53]. Physics engine: not stated (no PhysX/other name given).
- Sim timestep: dt = 1/60 s. Control rate: 20 Hz (Sec 4).
- Parallel envs: 8192 (Table 7, both teacher and student). GPU / wall-clock training time: not stated.

## B. Learning block
- Paradigm: RL (teacher, PPO with privileged information) → supervised teacher-student distillation (student, proprioception + tactile only).
- Algorithm: PPO [52] via rl-games [56] (teacher); TCN-encoder + MLP-policy student trained by supervised learning, initialized from the teacher's policy weights, per RMA [57] (Sec 3.2).
- Teacher-student / privileged→real distillation: yes. Privileged info xt (teacher only, Table 5): object position po(3), orientation ro(4), angular velocity ωr(3), dimensions dimo(2), center of mass COMo(3), mass mo(1); gravity vector ĝ(3); auxiliary-goal position pg(3), orientation rg(4). Student loss: MSE of latent vectors zt vs teacher's z̄t, plus NLL of the action distributions at vs āt (Sec 3.2). "Whilst the gravity vector can be inferred using the end effector pose of the robot arm, we did not find any benefit of explicitly including this information in the policy" — suspected to be implicitly inferable from a history of proprioception + contact forces (Appendix A).
- Observation ot (Table 4, real-world available to both teacher and student): Proprioception — joint position q (16), fingertip position f^p (12), fingertip orientation f^o (16), previous action a_{t-1} (16), target joint positions q̄ (16); Tactile — binary contact c (4), contact pose P (8), contact force magnitude F (4); Task — target rotation axis k̂ (3). Full-touch input dim N=95 (79 proprioception+task, +4 binary-touch → 83, +8 pose +4 force → 95), matching Sec 4/Appendix G's stated N=79/83/95 for the proprioception/binary/full-touch ablations.
- Action space: at := Δθ ∈ R^16, relative joint positions; EMA smoothing on the target: q̄t = q̄_{t-1} + ãt, ãt = ηat + (1-η)a_{t-1} (η value not stated); control at 20 Hz; Δθ ∈ [-0.026, 0.026]^16 rad (Sec 3.1).
- Domain randomization (Table 6, Appendix E), quoted ranges:
  - Object: Capsule Radius (m) [0.025, 0.034]; Capsule Width (m) [0.000, 0.012]; Box Width (m) [0.045, 0.06]; Box Height (m) [0.045, 0.06]; Mass (kg) [0.025, 0.20]; Object Friction 10.0; Center of Mass (m) [-0.01, 0.01]; Disturbance Scale 2.0; Disturbance Probability 0.25; Disturbance Decay 0.99.
  - Hand: PD Controller Stiffness ×U(0.9,1.1); PD Controller Damping ×U(0.9,1.1); Hand Friction 10.0; Observation Joint Noise 0.03; Observation Fingertip Position Noise 0.005; Observation Fingertip Orientation Noise 0.01.
  - Tactile: Observation Pose Noise 0.0174; Observation Force Noise 0.1.
  - Plus (stated separately in the text, not in Table 6): "the initial grasping pose, target rotation axis and hand orientation" are also randomized (Sec 4/Appendix E preamble).

## C. Reward / objective block (Appendix B, quoted/near-verbatim; most equation bodies recovered by OCR, see below)
Full reward decomposition, recovered from OCR: "r = r_rotation + r_contact + r_stable + r_terminate" (Eq. 2), where "r_rotation = λ_kp*r_kp + λ_rot*r_rot + λ_goal*r_goal", "r_contact = λ_rew(λ_gc*r_gc + λ_bc*r_bc)", "r_stable = λ_rew(λω*r_ω + λ_pose*r_pose + λ_work*r_work + λ_torque*r_torque)", "r_terminate = λ_penalty*r_penalty" (recovered by OCR from papers/md/anyrotate_2024.ocr.md; OCR text is noisier than the layout parse, symbols may be imperfect). This gives 9 named component terms (r_kp, r_rot, r_goal, r_gc, r_bc, r_ω, r_pose, r_work, r_torque) plus the termination term r_penalty.
Base reward terms and their exact weights, quoted from Appendix B.1: "The corresponding weights for each reward term is: λ_kp = 1.0, λ_rot = 5.0, λ_goal = 10.0, λ_gc = 0.1, λ_bc = 0.2, λω = 0.5, λ_pose = 0.5, λ_work = 0.1, λ_torque = 0.05, λ_penalty = 50.0."
- *Keypoint Distance Reward*: functional form recovered by OCR: "r_kp = dkp / (eax + b + e−ax)" where "dkp" appears to stand for the keypoint distance (OCR renders the numerator variable as "dkp", distinct from the "kp_dist" name used in the surrounding prose — quoted exactly as OCR gives it, symbol may be imperfect) (recovered by OCR from papers/md/anyrotate_2024.ocr.md; OCR text is noisier than the layout parse, symbols may be imperfect). Uses "keypoint distance kp_dist = (1/N)Σ_{i=1}^N ||k_i^o − k_i^g||", with "N = 6 keypoints placed 5 cm from the object origin in each of its principle axes, and the parameters a = 50, b = 2.0".
- *Rotation Reward*: "r_rot = clip(ΔΘ · k̂; −c1, c1)"; "represents the change in object rotation about the target rotation axis. We clip this reward in the limit c1 = 0.025 rad."
- *Goal Bonus Reward*: sparse bonus "where we use a keypoint distance tolerance d_tol to determine when a goal has been reached" (d_tol = 0.15 for teacher, 0.25 for student per Table 7).
- *Good Contact Reward*: "n_tip_contact = sum(c). This rewards the agent if the number of tip contacts is greater or equal to 2 to encourage stable grasping contacts."
- *Bad Contact Penalty*: "n_non_tip_contact is defined as the sum of all contacts with the object that is not a fingertip. We accumulate all the contacts in the simulation to calculate this."
- *Angular Velocity Penalty*: "the maximum angular velocity ω_max = 0.6. This term penalises the agent if the angular velocity of the object exceeds the maximum."
- *Pose Penalty*: "q_0 is the joint positions for some canonical grasping pose" (distance-based penalty from q_0).
- *Work Penalty* / *Torque Penalty*: recovered by OCR: "Work Penalty: rwork = −τ^T q̄" (Eq. 10) and "Torque Penalty: rwork = −||τ||" (Eq. 11) — the OCR labels BOTH equations "rwork"; Eq. 11 is almost certainly meant to be r_torque given the surrounding text and the λ_torque weight, but the label is quoted exactly as OCR gives it and this is flagged as a likely OCR (or original-PDF) labeling artifact, not corrected. (recovered by OCR from papers/md/anyrotate_2024.ocr.md; OCR text is noisier than the layout parse, symbols may be imperfect) "controller work-done penalty"; torque penalty uses "τ", "the torque applied to the joints during an actioned step."
- *Termination Penalty*: two conditions — object falls out of grasp, "maximum keypoint distance of d_max = 0.1"; rotation-axis deviation from target k̂_o beyond "k̂_max = 45°."
- Adaptive curriculum coefficient (Appendix B.3): "λ_rew(r_contact + r_stable) which increases with successive goals ... reached per episode", active over range [g_min, g_max] = [1.0, 2.0].
- Alternative reward (Appendix B.2, ablation "w/o auxiliary goal" used in Fig. 5): angular-velocity reward with c2 = 0.5, and a rotation-axis penalty on ||k̂_o||; "r_rotation = λ_av r_av + λ_rot r_rot", weights λ_av = 1.5, λ_axis = 1.0, and λω set to 0 (angular-velocity penalty removed) — all other terms unchanged.

## D. Contact / penetration handling
Not framed as interpenetration in the paper; instead handled through the Good/Bad Contact reward terms above (rewarding ≥2 fingertip contacts, penalizing "any other parts of the hand" contacting the object) and a fixed contact-force threshold of 0.25 N to derive binary contact (Appendix F). No contact-solver stiffness/damping/friction-iteration settings for IsaacGym itself are given; object/hand friction coefficients are set to 10.0 in domain randomization (Table 6). No penetration-depth metric is reported anywhere in the text.

## Evaluation
- metrics (exact definitions, Sec 4, "Evaluation"): "(i) Rotation Count (Rot) - the total number of rotations about the desired axis achieved per episode. In the real world, this is manually counted using reference markers attached to the object ... (ii) Time to Terminate (TTT) - time is taken before the object gets stuck, falls out of grasp, or if the rotation axis has deviated away from the target." Each episode/experiment run for 600 steps ("equating to 30 seconds").
- headline numbers: Table 1 (sim, OOD Mass / OOD Shape test sets): Dense Touch (Ours) Rot 2.18±0.05 / EpLen 22.8±0.8 (OOD Mass), Rot 1.77±0.01 / EpLen 27.2±0.3 (OOD Shape) — best of all ablations; a Fixed-Hand-Orientation policy scores only Rot 0.55±0.06 / 0.55±0.04 on the two sets, "suggesting gravity invariance adds considerable complexity to the task" (Sec 5.2). Table 2 (real, z-axis rotation across 6 hand orientations): Dense Touch best in every orientation, e.g. Palm Up Rot 1.57±0.57 / TTT 30.0±0.0 down to weakest Thumb Down Rot 0.91±0.33 / TTT 29.2±2.0. Table 3 (real, palm-down, per rotation axis): Dense Touch x-axis Rot 1.33±0.50/TTT 28.6±2.8, y-axis 0.79±0.37/27.8±4.8, z-axis 1.33±0.44/28.2±3.1. Tables 12/13 (Appendix K.3) break the same metrics down per real object.
- baselines beaten: Proprioception-only, Binary Touch, and Discrete Touch (the discretized contact-location representation from [8]), all re-trained by the authors in the same pipeline (Table 1); a Fixed-Hand-Orientation-trained policy as an ablation for the gravity-invariance claim.
- real robot? 16-DoF Allegro Hand on a UR5, with custom tactile fingertips, tested on 10 real objects (Table 10) across 6 hand orientations (palm up/down, base up/down, thumb up/down — Fig. 1) and x/y/z rotation axes. Exact number of trials/episodes per condition is not stated (only that each run lasts 600 steps / 30 s); reported values are means ± std, implying repeats, but the repeat count is not given.

## E. Evaluation block (additional, Appendix K.1)
- Success criterion: not stated as a binary success threshold; performance is reported continuously via Rot and TTT (no explicit "success = " definition found in the source). Appendix K.1 does report a "#Success" column (successive goals reached per episode) for the goal-tolerance/goal-increment ablation (Table 11), e.g. best setting d_tol = 0.25, θ = 30°: Rot 1.77, TTT 27.2 s, #Success 5.26.
- Eval episode/seed counts: not stated numerically anywhere in the extracted text.
- Sim vs real: Table 1 is sim; Tables 2, 3, 12, 13 are real; Appendix K.2 (Figs 12–13) directly compares simulated vs. real tactile-feature traces for the same rollout type, noting "a sim-to-real gap in the rotation speed" but "a matching pattern ... from the recorded contact features."
- Baselines re-run vs quoted: all ablation baselines (Proprioception, Binary Touch, Discrete Touch) appear to be re-trained by the authors within their own pipeline, not numbers quoted from the cited prior papers.

## Limitations stated by the authors
"We found the policies had difficulties with objects that have sharp geometric features, such as corners or edges, and rotating with these features required a more adaptive policy." Also: "the actuation of the Allegro Hand was significantly weakened under certain hand orientations. Therefore, designing low-cost and more capable hardware is crucial for advancing dexterous manipulation" (Sec 6, Conclusion and Limitations). Real-world per-object results (Appendix K.3) additionally note the gum box was "the most challenging due to its sharp corners and shifting mass (sloshing gum pieces)."

## Quotable claims (verbatim, with section)
- "Our formulation allows the training of a unified policy to rotate unseen objects about arbitrary rotation axes in any hand direction" (Abstract).
- "Gravity invariance is considered by randomly initializing hand orientations between episodes" (Sec 3.1).
- "we demonstrate that the trained policy can adapt effectively to a rotating hand where the gravity vector is continuously changing in the hand's frame of reference. ... This capability to manipulate objects during angular movements of the hand enables 6D reorientation of the object while simultaneously repositioning the grasp location" (Sec 5.3, Gravity Invariance).
- "The performance dropped as the hand directions changed from palm up and palm down, followed by base up and base down, to the thumb up and thumb down directions. We attribute this to the larger sim-to-real gap when fingers are positioned horizontally during manipulation" (Sec 5.3).
- Tactile sensor design: "This design of the sensor is based on the DigiTac version [39] of the TacTip [37, 58], a soft optical tactile sensor that provides contact information through marker-tipped pin motion under its sensing surface" (Appendix J).
