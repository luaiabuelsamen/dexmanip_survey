# dexndm_2025 — DexNDM: Closing the Reality Gap for Dexterous In-Hand Rotation via Joint-Wise Neural Dynamics Model (Liu et al.; arXiv 2510.08556, 2025)

sources: papers/md/dexndm_2025.md [856b1304] ; no code

## One-line contribution
A joint-wise neural dynamics model — each joint's next state predicted from only its own state-action history — is fitted on real data collected by an autonomous "Chaos Box" (hand immersed in a bin of soft balls, replaying sim-policy actions), then used to train a residual policy that corrects a sim-trained generalist's actions; the factorization is claimed (and given a KL-contraction proof) to be far more sample-efficient and better-generalizing than a whole-hand dynamics model (Abstract; Sec. 3.3).

## Setting
- hand(s): LEAP hand (Shaw et al., 2023), fingertip span 9.50 cm; arm: Franka (real-world only; Sec. C, "Real-World Hardware Setup"). Baseline comparisons also reference Allegro (10.05 cm span) and D'Claw (19.10 cm span) (App. C, "Robotic Hand Sizes"). Single hand, not bimanual.
- simulator / physics: Isaac Gym (Makoviychuk et al., 2021) for the oracle/generalist RL stage (Sec. 4.1); cross-simulator ("sim-to-sim") transfer additionally evaluated in Genesis and MuJoCo (Sec. 4.2, App. C). Timestep not stated; control is torque, 20 Hz control rate with the low-level torque loop run 6× per control step (App. A.1, "Control Strategy"): τ_t = K_p(q_t^tar − q) − K_d q̇. Training envs: "30,000 for cylinders and cuboids, ... 50,000 for long cuboids, small cylinders, and 'DexEnv Objects'" (App. C, "Policy Optimization"). GPUs: dynamics-model / residual-policy training on 8×A10 (App. C: sim-to-sim residual policy "about 13 hours"; real-world residual policy "about 10 hours ... using eight A10 GPUs"). Real hardware runs positional control at 20 Hz with PD gain/damping 800/200 (App. C).
- observation: oracle policy — 3-step joint position history (48-dim), 3-step joint positional-target history (48-dim), joint velocity (16-dim), fingertip state+velocity (52-dim), object state+velocity (13-dim), object guiding goal pose (4-dim), joint/rigid-body forces (40-dim), contact force + binary contact (92-dim), wrist orientation quaternion (4-dim), rotation axis (3-dim) (App. A.1, "Observations" — itemized exactly as printed). Generalist (BC) policy observation: history of {q_k, a_{k-1}} for k = t-T+1..t with T=10, plus wrist orientation and rotation axis (Sec. 3.2) — object state is NOT in the generalist's input (privileged-to-real distillation drops the object).
- action space: relative joint-target deltas, Δa_t ~ π(o_t), accumulated as a_t = a_{t-1} + α·Δa_t with α = 1/24, converted to torque via PD (Sec. 3.1). The residual policy at deployment outputs a correction a_t^res added to the base action: a_t + a_t^res (Sec. 3.3).
- objects / data: five training categories built from Hora (Qi et al., 2022) cylinders/cuboids, custom long cuboids, small cylinders, and Visual Dexterity (Chen et al., 2022) "DexEnv Objects" (App. C, Table 9). ContactDB (Brahmbhatt et al., 2019) objects held out as the sim generalization test set (Sec. 4.1). Real-world test sets: regular objects incl. a high-aspect-ratio cuboid, small objects, normal-sized irregular objects (Fig. 5); aspect ratios up to 5.33, object-to-hand ratio 0.31–1.68 (Sec. 1).

## Method
- paradigm: RL (specialist experts) → BC distillation (generalist) → supervised residual-policy fitting against a learned dynamics model (sim-to-real correction). Sec. 3 gives the pipeline as (A) oracle training, (B) BC generalist, (C-E) neural sim-to-real.
- algorithm: PPO (Schulman et al., 2017) in Isaac Gym for per-category oracle experts (Sec. 4.1); BC (supervised) for the generalist, trained only on successful oracle rollouts (Sec. 3.2, "aggregate only successful trajectories"); the joint-wise dynamics model f_ψ^i and residual policy π^res are trained by supervised regression against real (or target-sim) transitions (Sec. 3.3).
- teacher-student: oracle policies are privileged (object state + contact forces + goal pose in observation, per-category); generalist is BC-distilled from aggregated successful oracle rollouts and drops object state entirely, keeping only proprioceptive history + wrist orientation + rotation axis (Sec. 3.2). Authors explicitly rejected DAgger-style distillation here: "even single-policy distillation either fails to optimize in simulation or collapses in the real world, echoing PenSpin" (Sec. 3.2).
- domain randomization: "randomization ranges of each object set are summarized in Table 9" (values not in the parsed text/table). A random disturbance force of scale 2m (m = object mass) is applied and resampled each step with probability 0.25; joint-position noise ~U(0, 0.005) is added (App. C, "Domain Randomization"). An "Automatic System Identification" pass separately identifies per-joint PD gains and per-link mass by replaying probing trajectories in both sim and real and picking the closest-matching simulated parameter set (App. C; Tables 11–12 values not in parse).

## Reward / objective block (quoted)
- RL reward (Sec. 3.1, restated with full form in App. A.1): "r = α_rot r_rot + α_goal r_goal + α_penalty r_penalty, with r_rot and r_penalty following RotateIt (Qi et al., 2023)."
  - r_rot = clip(ω_t · k, −c, c), k the unit target axis, c = 0.5 (App. A.1).
  - r_penalty = −α_rotp‖ω_t × k‖_1 − α_lin‖v_t‖_2^2 − α_pose‖q_t − q_init‖_2^2 − α_work·τᵀq̇ − α_torque‖τ‖_2^2, with α_lin=0.3, α_pose=0.3, α_torque=0.1, α_work=2.0, α_penalty=1.0. α_rotp is scheduled: 0 for the first 10 resets, linearly ramped to 0.1 between resets 10–100, then held at 0.1 (App. A.1).
  - r_goal (added because "solely relying on these rewards cannot solve challenging problems like rotating a long object"): a waypoint 90° ahead on the target axis, re-set whenever within 15°; r_goal = clip((ang_diff(p_t, p_goal) + ε)/c_goal, 0, ·) [sign/direction as printed is garbled by the PDF parse — the term is a clipped angular-distance-to-waypoint penalty plus a threshold bonus g_bonus·1[ang_diff < c_threshold]]; α_goal = 1.0 (App. A.1). Note: the exact sign/normalization of r_goal is mangled in the OCR (superscript/subscript soup) — quoted as parsed, flagged as ambiguous.
- Residual-policy objective (Sec. 3.3, quoted form): π_res* = argmin_π^res E_τ~p_π*(τ) Σ_{t=1}^{N-1} ‖q_{t+1} − f_ψ({q_j, a_j + π^res(o_j^gene, a_j)}_{j=t-W+1}^t)‖ — i.e., the residual is fit so that the learned dynamics model, driven by base+residual actions, matches the simulator's next state. Trained "in a supervised manner on the trajectory dataset used to train the base policy."
- Dynamics model loss: not given as an explicit named loss in the main text beyond "learns each joint's evolution from its own dynamic profile"; App. D gives the compensator reward used only for the ASAP/UAN re-implementation baselines: r^compensator = −‖q_t^ref − q‖_2 (free-hand finetuning) and, for sim-to-sim, r^compensator = −k_h‖q_t^ref − q‖_2 − k_o·ang_diff(o_t^ref, o_t) with k_h=1.0 and k_o curriculum-ramped from 0.001 (App. D) — these are baseline-only, not DexNDM's own objective.
- No code repo exists for this key, so none of the above can be cross-checked against an implementation; all reward terms are as printed in the PDF text/appendix only.

## Contact / penetration handling
Not addressed as a measured or penalized quantity. The paper's only interpenetration-adjacent statement is about the LEAP hand itself: "actuating the joint between mcp link to pip link when fixing other joints would lead to self-collision" during base-wave data collection, so those joints are excluded from that ablation baseline (App. C). No hand-object penetration metric, contact solver setting, or penetration term appears anywhere in the reward, observation, or evaluation. Contact is represented only as force magnitude/binary-contact observations (92-dim block, App. A.1) and a soft-contact assumption invoked in the Theorem 3.1 proof sketch (App. A.2, citing Pang & Tedrake's soft contact model) — this is a modeling assumption for the dynamics-factorization proof, not a penetration measurement.

## Evaluation
- metrics (Sec. 4.1, "Metrics", from RotateIt): Time-to-Fall (TTF) — sim episodes capped at 400 steps (20 s), normalized by 20 s; real TTF reported in raw seconds. Rotation Reward (RotR) = episode sum of ω·k (sim only). Rotation Penalty (RotP) = per-step average ω×k (sim only). Radians Rotated (Rot) — real-world only. Goal-Oriented Success (GO Succ., sim only, from Visual Dexterity): success if final orientation within 0.1π of a sampled goal pose.
- headline numbers: Table 1 (sim, ContactDB unseen test objects) — DexNDM generalist beats re-implemented AnyRotate on every axis group and GO Succ. (88.27±3.21 vs 64.33±4.70). Table 2 — vs. AnyRotate's own reported real numbers on 4 replicable objects (Cube, Container, Tin Cylinder, Gum Box): e.g. Cube Rot 39.10±4.75 rad / TTF 198.39±21.65 s (DexNDM) vs. AnyRotate 6.53±1.32 rad / 24.00±4.30 s. Tables 4–5 (real, palm-down multi-axis and multi-wrist-pose z-rotation) show DexNDM > Whole-Hand-NDM ablation > Direct-Transfer-without-adaptation baseline throughout, e.g. palm-down z-axis on regular objects: Direct Transfer 11.69±0.30 rad/21.67±2.74 s, Whole Hand NDM 7.38±0.49/16.33±1.79 s, DexNDM 23.82±3.86/37.50±5.02 s.
- trial counts: real-world numbers are "averaged over objects and reported as mean ± standard deviation across three independent evaluations" (Sec. 4.1) — i.e. n=3 independent trial repeats per condition, each itself averaged over the object set; the number of objects per set and per-trial episode count are not stated numerically in the parsed text beyond the object lists in Fig. 5.
- sim-to-sim (Genesis, MuJoCo): "our method consistently surpasses prior work" against UAN/ASAP cross-simulator transfer (Isaac Gym → Genesis/MuJoCo); Genesis run collected via 30,000 envs up to 1.5M rollout attempts, kept 3,280,673 successful trajectories; MuJoCo run used 1 env, 4,000 trajectories per training cylinder (36,000 total), kept 23,650 successful trajectories; evaluated on ContactDB test objects over 10 initial grasps per object, mean±std of per-object averages (App. C). No numeric table value for this comparison survived the parse (the printed table is malformed as "Table 4.2" with no cell data) — treat as SOURCE THIN.
- baselines: AnyRotate (Yang et al., 2024, re-implemented in sim — "code is unavailable"; on hardware compared to AnyRotate's own reported numbers on replicable objects), Visual Dexterity (Chen et al., 2022 — code adaptation to LEAP "failed to achieve reasonable performance ... even after 1.5 days of training," so compared only via a new "survival rotation angle" metric estimated from their published videos), UAN (Fey et al., 2025) and ASAP (He et al., 2025) re-implemented and adapted from legged/arm domains to the hand — both "fail entirely in real-world tests—unable to rotate even a simple cylinder" (Sec. 4.2). A Whole-Hand Neural Dynamics ablation (same pipeline, non-factorized dynamics model) is the main ablation baseline (Tables 4–5, Fig. 6).
- real robot? LEAP hand + Franka arm, trial counts as above (n=3 repeated real evaluations, object sets in Fig. 5); not video-only — quantitative Rot/TTF numbers with mean±std are reported (Tables 4, 5), though per-object/per-trial episode counts are not spelled out as a raw N. The Visual Dexterity comparison (Table 3, survival-angle counts) is explicitly derived from "carefully examining all of its demos present in all videos from its website" for the baseline side, so that comparison is baseline-video-only even though DexNDM's own side is live hardware.

## Limitations stated by the authors (Sec. 6)
- "The main limitation is that the model's ceiling is restricted by partial observations; jointly modeling hand–object transitions from richer signals, and integrating tactile are valuable future directions."
- (Implicit elsewhere) direct real-hardware comparison to AnyRotate was impossible because reproducing AnyRotate's tactile sensor model and second-stage sim-to-real method was infeasible without their code (App. C); direct comparison to Visual Dexterity's code on LEAP failed to train in sim at all (App. C).

## Quotable claims (verbatim, with section)
- "no prior work demonstrates robust, in-the-air rotation for a wide spectrum of objects—including complex shapes, high aspect ratios, and varied sizes—under diverse wrist orientations and rotation axes." (Sec. 1)
- "In simulation, our base policy generalizes to novel, complex shapes, outperforming strong baselines by 37%–81%." (Sec. 1)
- "even single-policy distillation either fails to optimize in simulation or collapses in the real world, echoing PenSpin (Wang et al., 2024)." (Sec. 3.2)
- "A simple extrapolation suggests matching our 4,000-trajectory result would require 7.5M task-aware trajectories (417k hours; 52k 8-hour workdays), which is impractical." (Sec. 5)
- "We attribute this to an OOD issue: compensators trained solely on free-hand data do not generalize to the interaction dynamics introduced by manipulated objects." (Sec. 4.2, on UAN/ASAP failure)

## Notes for the survey
- Genuinely new vs. 2022-2023 (RotateIt/Hora, Visual Dexterity, AnyRotate): (1) the joint-wise factorization of a real-world dynamics model (vs. whole-hand neural dynamics or system-ID baselines) with a KL-contraction generalization argument (Sec. 3.3, App. A.2); (2) the "Chaos Box" autonomous, human-intervention-free real-data-collection method (randomized soft-ball loads + replayed sim actions) as an alternative to task-aware rollouts or parameterized wave injection; (3) demonstrated generality across aspect ratio (up to 5.33), small object size (down to 3 cm), and six wrist orientations simultaneously, which the cited baselines each cover only one axis of. The base RL reward (r_rot, r_penalty) is explicitly inherited unchanged from RotateIt (Qi et al., 2023); the goal-waypoint term r_goal is the one new reward addition, added specifically because rotating long/high-aspect-ratio objects failed without it.
- Feeds: sim-to-real transfer section (contrasts DR/SysID/adaptive-policy/neural-dynamics-modeling taxonomy, App. D, useful as a general framework reference); reward-design comparison (reward terms are borrowed wholesale from a 2023 baseline, only the curriculum-scheduled goal term is new — worth contrasting with papers that redesign the reward from scratch); real-robot evaluation-rigor section (n=3 repeated-trial protocol, explicit acknowledgment that a competing baseline's numbers were read off videos, not rerun).
- No interpenetration handling anywhere — flag as an example of a recent (2025) sim-to-real in-hand paper with zero penetration measurement or reward term, for the survey's contact/penetration-handling comparison table.
