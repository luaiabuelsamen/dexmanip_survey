## One-line contribution
The Python-bindings layer (PyBullet) over the Bullet Physics SDK, described in its own citation entry as providing "improved support for robotics, reinforcement learning and VR" over using Bullet's C++ API directly (README).

## Setting
- hand(s) shipped as assets: **not confirmed from the parsed material.** The pruned file tree explicitly excludes most asset/data files ("assets pruned"), so URDF/robot-model files could not be checked directly. The only "hand"-named source files present are VR/teleoperation input scripts — `examples/pybullet/examples/hand.py`, `vrhand.py`, and `vrhand_vive_tracker.py` — which read from a hand-tracking/glove peripheral (`getSerialOrNone`, `convertSensor` functions) to drive a simulated end-effector; these are teleoperation input plumbing, not a shipped dexterous-hand robot model, and no Allegro/Shadow/LEAP-style URDF was located in the parsed manifest. This should be treated as "not stated" rather than "none," since assets were pruned from the crawl.
- simulator / physics: PyBullet wraps the Bullet C-API; "the entire collision detection and rigid body dynamics can be executed on the GPU" via an experimental OpenCL path (README, "Requirements for experimental OpenCL GPGPU support"), separate from the default CPU path.
