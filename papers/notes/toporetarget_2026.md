## One-line contribution
TopoRetarget retargets human hand-object mocap (MediaPipe hand keypoints + object mesh) to a dexterous robot hand by building a shared sparse interaction graph (Delaunay tetrahedralization over 21 hand keypoints + 50 object surface samples) and solving a topology-aware, distance-weighted Laplacian-coordinate-matching optimization with explicit penetration constraints — producing references that a minimal PPO tracking controller can follow far more reliably than four retargeting baselines, especially on contact-mode-switching pen-spinning (Abstract; Sec. 3-4).

## Setting
- hand(s): "Wuji Hand" (dexterous robot hand; zero-shot real deployment target for cube reorientation and pen spinning), n_θ actuated finger joints (count not stated numerically); right-hand-only downstream RL task (App. A.5: "single-hand object manipulation ... with a right dexterous hand"). No arm (floating base — "floating-base retargeting" and a base-pose prior in the optimization, App. A.1); not bimanual.
- simulator / physics: not named (no simulator engine string in the parsed text); domain randomization applied over "object mass and center of mass, contact parameters, actuator gains, joint damping, and hand-link inertial properties" plus external object perturbations during rollout (Sec. 4, "Domain randomization"); number of parallel envs and GPU not stated.
- observation (App. A.5.2): three parts — proprioception (current finger joint positions, velocities, previous action); object observation (object pose in base frame represented via a small set of object "axis points" rather than a quaternion, "to avoid direct dependence on a particular quaternion parameterization while still encoding position and orientation"); reference observation (current reference joint pose, object axis points, tracked hand-link positions, plus lookahead reference features at offsets of 1, 3, and 5 control steps). Small noise added to proprioception and observed object pose during training.
- action space: residual joint-position command for n_θ right-hand finger joints, applied on top of the current reference pose: q_t^{θ,tar} = q_{kt}^{θ,ref} + a_t (App. A.5.1).
- objects / data: retargeting quality evaluated on the ContactPose Dataset [26], 25 of 28 grasps (excluding mug, scissors, Utah teapot for "deeply concave object geometry"). Downstream tracking policies trained/evaluated on two trajectory sets: Ho-cap [31], 32 grasp-centric single-hand sequences (randomly drawn subset); and the authors' own self-collected MoCap Pen-Spin Dataset, 32 pen-spinning demonstrations recorded with mocap + the "Wuji Glove," averaging 12.4s with frequent non-tip contacts and contact-mode transitions (Sec. 5, App. A.4). Human hand data captured as MediaPipe 21-keypoint hand trajectories P_{1:N}^h ∈ R^{21×3} (Sec. 3.1).

## Method
- paradigm: retargeting (constrained optimization, not learned) followed by RL tracking ; algorithm: retargeting is a two-stage optimization (bone-direction initialization → topology-aware Laplacian refinement), not RL; downstream tracking is PPO [29] (Sec. 3, Sec. 4).
- human dataset retargeting (the paper's core contribution, Sec. 3): correspondence is over 21 MediaPipe hand keypoints P_t^h plus N_o=50 object-surface samples, giving N_v = 21+50 interaction-graph vertices per frame. Two-stage optimization: (1) **Relative Bone-Direction Initialization** (Sec. 3.2) — matches per-finger bone-direction unit vectors d_k (source→robot) between corresponding non-terminal keypoints along each finger, weighted by λ_warm=1 for the bone-direction term and λ_smooth=2.5 for temporal consistency with the previous frame's initial estimate, giving an initial guess q̃_t^r (this stage has no object/contact information, it purely aligns finger articulation). (2) **Topology-Aware Laplacian Optimization** (Sec. 3.3-3.4) — builds a shared interaction graph via Delaunay tetrahedralization on the source vertex set V_t^s (hand keypoints + object samples), reuses that edge connectivity I_t for the robot vertex set V_t^r(q); computes source-frame distance-aware edge weights with spatial decay κ=30; matches weighted Laplacian coordinates of source vs. robot graphs (E_IM, "interaction-mesh energy"); the final optimization combines E_IM (λ_IM=500), a bone-direction prior term E_bone (λ_bone=0.1) carried over from stage 1, and a smoothness/base-pose regularizer E_reg (λ_reg=2.5, plus floating-base translation prior λ_base,pos=100 and rotation prior λ_base,rot=1), subject to hard kinematic constraints and a penetration constraint using signed-distance queries φ_i(q) with soft tolerance τ=0.001 m, hard bound b=0.030 m, and slack penalty weight w_s=1.0×10^5 (Table 3, App. A.1). One fixed parameter set is used across all experiments — "rather than performing extensive per-case tuning" (Sec. 3.4). The interaction graph is rebuilt (not re-targeted from scratch) when the object is rescaled or the hand embodiment changes, supporting augmentation "without per-case retuning" (Sec. 3.3, Sec. 5.3).
- reward (paper + Table 4, App. A.5.4, quoted with tolerances): Gaussian tracking kernel ψ(e;σ)=exp(−‖e/σ‖²). Object term = ψ(mean over 6 object-axis-point position errors; σ=0.04 m), weight 8.0. Link-position term = ψ(mean over L tracked hand-link position errors; σ=0.025 m), weight 1.0. Joint-position term = ψ(mean over n_θ normalized joint errors, normalized by (q_j^max−q_j^min); σ=0.1 [dimensionless, fraction of joint range]), weight 1.0. Action-smoothness term = ‖a_t−a_{t-1}‖² + ‖a_t−2a_{t-1}+a_{t-2}‖², weight −0.01. Total r_t = w_obj·r_obj + w_link·r_link + w_joint·r_joint + w_smooth·r_smooth. "In practice, the largest weight is assigned to object tracking, followed by link, joint, and smoothness terms."
- key trick(s): sharing one Delaunay-derived graph topology between source and robot so Laplacian coordinates are compared "under the same local hand-object neighborhood structure" rather than via absolute distance matching; a residual joint-position action on top of the reference (not raw joint targets), letting the RL policy stay close to the retargeted reference while correcting for tracking error; base-frame-relative object/link references so the policy learns hand-object interaction rather than global trajectory tracking.

## Evaluation
- retargeting-quality metrics (App. A.3, Sec. 5.1, quoted): Contact precision E_prec — mean object-relative position displacement of in-contact links (mm), where the in-contact link set C comes directly from ContactPose's own sigmoid-normalized, thresholded per-vertex contact annotations, attributed to the nearest of 20 hand bones, with a link marked "in contact" if ≥10 vertices land on it. Contact alignment E_align — mean object-relative orientation error of in-contact links (degrees). Penetration: max penetration depth (mm, via signed distance d_{Mt}(x) over sampled robot-hand surface points X_t^r against the posed object mesh M_t, positive = outside) and "% frames with penetration >2mm" (δ=2mm threshold) — both explicitly reported quantitative penetration metrics, not just qualitative claims.
- headline numbers (Table 1, ContactPose, 25 grasps): TopoRetarget contact precision 7.71mm, contact alignment 15.67°, max penetration 1.07mm, %frames penetration>2mm = 0.00%, solve time 4.70ms/frame. Baselines: OmniRetarget 14.15mm/30.80°/1.15mm/0.00%/40.96ms; Mink 14.12mm/37.36°/20.12mm/84.00%/4.37ms; DexPilot 14.13mm/33.71°/11.87mm/88.00%/1.74ms; GeoRT 26.77mm/25.74°/22.22mm/96.00%/1.17ms. Downstream tracking (Table 2): Ho-cap (32 clips) — TopoRetarget success 84.4% (27/32), obj. pos err 0.87cm, obj. rot err 5.76°; best baseline (Mink/DexPilot/GeoRT tied) 75.0% (24/32); OmniRetarget 56.2% (18/32). MoCap Pen-Spin (32 clips) — TopoRetarget success 87.5% (28/32), pos err 0.98cm, rot err 9.25°, "over 40 percentage points above all baselines" (best baseline OmniRetarget 46.9%/15/32; the abstract's "40.6 percentage points" improvement figure refers to this comparison). Rollout success defined as "reaches the final reference frame without triggering the object-pose termination criteria in Appendix A.5" (Sec. 5.2).
- baselines beaten: OmniRetarget [27] (re-implemented for hands: humanoid interaction-mesh objective adapted to MediaPipe keypoints, wrist un-fixed, collision handling extended to full hand geometry — App. A.2), Mink [30], DexPilot [8], GeoRT [13] — all under identical human references, object geometry, RL architecture, reward, domain randomization, and termination criteria (Sec. 5.2).
- real robot? yes, qualitative only — zero-shot sim-to-real transfer to the Wuji Hand for cube reorientation and pen spinning (Fig. 4), but no real-world trial count or success rate is reported in the parsed text; described as a demonstration, not a quantified real-robot evaluation.

## Limitations stated by the authors (Sec. 7)
- Depends on upstream human-reference quality; explicitly handles contact distortion caused by *penetration* in the source motion, but "is less effective for virtual contacts, where the source finger is intended to interact with the object but does not actually touch the object surface" — i.e. it cannot recover from a demonstration that has a false negative (missing) contact, only from false-positive (penetrating) ones. Suggested future work: source-motion preprocessing to correct missing-contact cases before retargeting.

## Quotable claims (verbatim, with section)
- "The method constructs a sparse interaction graph over hand and object keypoints and optimizes distance-weighted Laplacian deformation with directional consistency, kinematic constraints, and penetration handling." (Abstract)
- "TopoRetarget also keeps penetration small, with a maximum penetration of 1.07 mm, and avoids the severe interpenetration observed in several baselines" (Sec. 5.1)
- "A rollout is counted as successful if it reaches the final reference frame without triggering the object-pose termination criteria in Appendix A.5." (Sec. 5.2)
- Termination table (Table 4, App. A.5.4): "Object unstable: Height < 0.06m, linear velocity > 10m/s, or angular velocity > 500rad/s"; "Object position error: ‖p_o − p_o^ref‖₂ > 0.05 m"; "Object orientation error: > 45°"; "Object axis-point error: Any of the 6 object axis-point errors > 0.05m"; "Timeout: Episode reaches 20 s."
- "Our method can handle contact distortion caused by penetration in the source motion, but it is less effective for virtual contacts" (Sec. 7)

## Notes for the survey
- Feeds: the retargeting-methods comparison table (TopoRetarget vs. OmniRetarget/Mink/DexPilot/GeoRT, all quantified on the same ContactPose benchmark — a rare case in this batch of directly comparable retargeting numbers); the block-D interpenetration section as the strongest positive example in this batch — penetration is measured quantitatively at the retargeting stage (max depth in mm + %frames >2mm) AND constrained explicitly during retargeting optimization (soft tolerance 1mm / hard bound 30mm slack-penalized at 1e5), though NOT independently re-measured after RL tracking (the RL reward/termination criteria in Table 4 govern object pose and joint tracking error, not hand-object penetration — so post-tracking interpenetration is unverified even though pre-tracking reference interpenetration is tightly controlled).
- Object tracking: position AND orientation, encoded jointly via 6 "object axis points" rather than a raw position+quaternion pair (App. A.5.2) — an implementation detail worth flagging when comparing observation/reward encodings across the survey's method table.
- Failure/termination: five distinct triggers, all with explicit numeric thresholds (Table 4) — 20s timeout; object height<0.06m or |v|>10m/s or |ω|>500rad/s ("unstable"); object position error>0.05m; object orientation error>45°; any of 6 axis-point errors>0.05m. Useful as a contrast point against physhoi_2023's single 0.5m position-error termination and omnigrasp_2024's 12cm/25cm two-threshold scheme.
- Retargeting vs. RL-reward reward terms should not be conflated: the "reward" table (Table 4) belongs to the downstream PPO tracking controller (Sec. 4/App. A.5), separate from the retargeting optimization's own objective (E_IM/E_bone/E_reg, Sec. 3.4) — this note's Method block keeps the two apart as the paper does.
