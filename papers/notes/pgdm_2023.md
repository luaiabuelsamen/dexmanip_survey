# pgdm_2023 — Learning Dexterous Manipulation from Exemplar Object Trajectories and Pre-Grasps (Dasari, Wang, Hong, Powell, Zhang, Ekvin, Gupta, Pathak; ICRA 2023)

sources: papers/md/pgdm_2023.md [sha256 c4a7bc47] ; no code

## One-line contribution
A single, per-task-tuning-free RL recipe — reward defined purely from an exemplar object
trajectory (TCDM, 50 tasks) plus initializing exploration at a pre-grasp hand pose (PGDM) —
matches or beats baselines that require full hand-trajectory imitation (DeepMimic), affordance
supervision (GRAFF*), or a hand-tuned curriculum, using no reward/observation supervision beyond
a single pre-grasp frame per task (Table I, Fig. 3).

## Setting
- hand(s)/robots: 3 platforms — ShadowHand [16] (24-DoF anthropomorphic), D'Hand [28], D'Manus
  [30] (low-cost RoBEL hand, used for real-world validation); arm: Franka Panda (real-world only,
  base pose otherwise a free joint in sim); single-handed throughout, no bimanual tasks.
- simulator / physics: MuJoCo [44]; object properties for ContactDB objects set via PLA density
  (1.25 g/cm^3) + VHACD convex decomposition to derive mass/inertia (since ContactDB objects are
  3D-printed); YCB object properties measured from real objects. Timestep/#envs/GPU/wall-clock
  not stated; training run to "50M samples" per task (Table I caption), 3 seeds/task.
- observation: "robot joints, robot fingertip locations, and the object pose," plus a positional
  encoding of the current simulation timestep appended to handle time-varying goals (Appendix
  B.3, "Observation Space"). State-based only, no vision.
- action space: joint position control via "a simple low level PD torque controller. The first
  six joints handle wrist position/orientation, and the remaining joints control the robot
  fingers"; gains tuned to be realistic, gravity compensation applied (Appendix B.3).
- objects / data: 34 objects from ContactDB [22] and YCB [23]; 50 tasks (TCDM-50) built from
  3 exemplar-trajectory sources (see below); a 30-task subset (TCDM-30, all GRAB-sourced except
  the 10 "simple lifting" GRAB tasks removed) used for baseline comparisons requiring full hand
  supervision.

## Method
- paradigm: pure on-policy RL (PPO [46]/[53] via Stable-Baselines3) with reward defined solely
  from an object-pose trajectory — NOT imitation learning on hand motion, and NOT reward learned
  from vision. No teacher-student/privileged-to-vision distillation (state-based throughout).
- **human data source and size**: exemplar object trajectories (the RL goal signal) come from
  three sources, only one of which is human motion-capture video/data: (1) "Human Motion Capture
  (GRAB [37])" — GRAB records "a human performing various skills with a collection of common
  objects... from the ContactDB dataset," providing paired object-pose trajectories and MANO hand
  mesh trajectories; "we created 40 tasks using trajectories from GRAB" (Appendix B.2). (2)
  "Expert Policies (ADROIT [24])" — object trajectories extracted from successful RL/teleop
  policy rollouts in the DAPG ADROIT suite (not human data), "3 tasks." (3) "Human Animators" —
  7 object trajectories hand-scripted/animated by a person, explicitly NOT from data ("object
  trajectories for our method need not come from data"). So of 50 tasks, only 40 (GRAB) are
  sourced from an actual human-demonstration dataset; the human-video/demo fraction of TCDM is
  40/50 = 80%, with the remainder synthetic. Pre-grasps (separate from trajectories) are sourced
  from 4 places: MoCap (GRAB, IK-transferred, 37 tasks per Table I), Tele-Op (DAPG dataset
  pre-grasp states, 3 tasks), Human Labels (manually annotated via the MuJoCo UI, 7 tasks), and
  Learned Model (GrabNet [37]-predicted MANO grasp pose, IK-transferred, 3 tasks).
- **what is extracted from video/demo data**: from GRAB, only the object's 6-DoF pose trajectory
  X = [x_1,...,x_T] is used as the RL goal signal — GRAB's accompanying human hand mesh
  trajectories H = [h_0,...,h_n] are explicitly "not used in our method, but are required for the
  baselines" (Appendix B.2). Separately, for pre-grasps, a single frame's human hand pose (finger
  joint articulation near first contact) is extracted and IK-retargeted to the robot; this is the
  only hand-shape information PGDM itself uses, and it is a single static frame per task, not a
  trajectory or reward signal.
- **human-to-robot mapping**: only for the pre-grasp frame, via "an inverse kinematics procedure
  (solve for joints that achieve human finger-tip positions)" (Appendix B.2, "MoCap") — a
  fingertip-position IK fit, not a full kinematic-chain retargeting scheme (contrast dexmv_2021's
  TSV optimization or dexvip_2022's parent-relative-frame retargeting). No mapping is applied to
  full trajectories or used at RL-training time beyond this one-shot pre-grasp initialization.
  Object trajectories are used directly (no retargeting needed since goals are object, not hand,
  poses).
- **RL or SL**: pure RL (PPO). The paper explicitly contrasts this with imitation-based
  approaches: "PGDM can learn effective policies using... no hand supervision outside of
  pre-grasps," which "defies conventional wisdom in the field that suggests human supervision is
  critical" (Sec. V-A). DeepMimic baseline (which does imitate the full hand trajectory) is
  implemented for comparison but is not the proposed method.
- reward or loss (Sec. III-A, quoted): `R(x_hat_t, x_t) := lambda_1 * exp{-alpha*||x_t^(p) -
  x_hat_t^(p)||_2 - beta*|angle(x_t^(o), x_hat_t^(o))|} + lambda_2 * 1{lifted}`, where
  `1{lifted} = x_t^(z) > zeta AND x_hat_t^(z) > zeta`. Termination:
  `T(x_t, x_hat_t) := ||x_t - x_hat_t||_2 > omega`. Hyperparameters (Table III, no per-task
  tuning): lambda_1=10, lambda_2=2.5, alpha=50, beta=5, zeta=0.02, omega=0.25. PPO
  hyperparameters: discount 0.95, GAE lambda 0.95, lr 1e-5, value-fn coef 0.5, entropy coef
  0.001, PPO clip 0.2, 4096 steps/iter, mini-batch 256, 5 epochs, policy/value nets MLP([256,128])
  with Tanh + orthogonal init. No reward term is video-derived beyond the object-trajectory goal
  itself; the object trajectory IS the reward target, quoted identically from paper and Table III.
- key trick(s): pre-grasp-based exploration initialization (robot hand teleported/planned to a
  hand-annotated pre-grasp state via a geometry-free CEM trajectory planner before RL begins,
  Appendix B.4a); decoupling task specification (object trajectory) from grasp supervision
  (pre-grasp) so that only one frame of hand information is ever needed per task.
- domain randomisation: none for the main 50-task benchmark (state-based sim only). For the
  single real-world validation task: "at every environment reset the cracker-box's width, mass,
  and friction are randomized within a pre-specified range" (Appendix E, "Simulated Policy
  Learning") — this is the only randomized-training instance in the paper.
- contact / penetration handling: not explicitly addressed as a penalty or metric — no
  interpenetration term in the reward. Pre-grasps are explicitly defined to be pre-contact
  states: "pre-grasps are not stable grasps. In fact, the hand does not make contact with the
  objects at all!" (Fig. 7 caption) — this describes contact TIMING relative to the pre-grasp,
  not a plausibility check on interpenetration.

## Evaluation
- metrics (Sec. IV-A "Success Metrics"): COM Error `E(X_hat) = (1/T) * sum_t ||x_t^(p) -
  x_hat_t^(p)||_2` (meters); Ori Error `E(X_hat) = (1/T) * sum_t angle(x_t^(o) - x_hat_t^(o))`
  (radians); Success `S(X_hat) = (1/T) * sum_t 1{||x_t^(p) - x_hat_t^(p)||_2 < epsilon}` with
  "epsilon = 1cm threshold" — fraction of timesteps within 1cm of the exemplar COM position.
  Authors note "humans easily perceive rollouts that score from 60-80% as 'successful'."
- headline numbers (Table I, averaged over 50 tasks, 3 seeds, at 50M training samples): overall
  Success 74.5%, COM Error 5.23e-3 m, Ori Error 0.33 rad. By pre-grasp source: MoCap (37 tasks)
  75.0% / 4.45e-3 / 0.32; Tele-Op (3) 84.5% / 1.12e-3 / 0.059; Labeled (7) 69.2% / 7.76e-3 / 0.42;
  Learned (3) 90.4% / 1.55e-3 / 0.18. Baseline comparison on TCDM-30 (Fig. 3/4): PGDM-only is
  competitive with or beats all 6 baseline variants (DeepMimic, GRAFF*, Task Curriculum, each
  with/without PGDM init); baselines "provide no appreciable performance boost (even when using
  PGDM), and are completely ineffective w/out PGDM." Pre-grasp ablation (Table II, TCDM-30):
  default pre-grasp 75.5% success / 4.82e-3 error; Ablate Pose "Open Hand" 23.1% / 1.55e-2;
  "Mean Hand" 59.5% / 5.90e-3; Ablate Distance 15cm offset 28.6% / 1.17e-2, 25cm offset 19.7% /
  1.92e-2 — object proximity and finger pose both matter significantly, with distance mattering
  more (removing it entirely tanks success to ~20-29%).
- baselines beaten: DeepMimic [34] (imitates expert fingertip poses + object trajectory, the
  maximum-supervision baseline), GRAFF* [29] (re-implemented with state instead of vision, reward
  for contact at ground-truth affordance points), Task Curriculum [32] (lift-first then
  linearly-activated full tracking reward over 4M steps) — all three author-re-implemented on
  TCDM-30, each with and without PGDM initialization; none exceeds PGDM-only despite using
  strictly more supervision.
- real robot? Yes, but minimal: single task ("Cracker-Box Lifting"), D'Manus hand mounted on a
  Franka Panda arm, YCB Cheez-It cracker-box. Policy trained in sim (with box width/mass/friction
  domain-randomized) then open-loop-replayed on hardware — "we are able to successfully lift the
  cracker-box object using the actions optimized in simulation. No real world adaptation or
  fine-tuning was required" (Appendix E, "Results"). No trial count, no success rate, no
  quantitative real-world metric is given — a single qualitative demonstration ("the robot grasps
  and lifts the cracker-box using the learned behavior," Sec. V-D). The authors explicitly caveat
  "this result does not prove that our actual policies can be transferred onto hardware" at scale.

## Limitations stated by the authors
- "our investigation was primarily conducted in simulation, which is quite common in this space
  due to the lack of affordable dexterous hands (ShadowHand is $100K+)" (Sec. VII).
- Pre-grasps were curated (human-labeled/MoCap/GrabNet), not predicted from vision in the wild:
  "this approach would not work 'in-the-wild' where objects are innumerable" (Sec. VII).
- Task formulation cannot encode precise force requirements (e.g. "hammering a nail with 15N
  force") and considers only single-object tasks without clutter/distractors (Sec. VII).
- Pre-grasp reaching uses a geometry-free heuristic planner that "will not scale to more
  complicated settings (e.g. reaching pre-grasp states in clutter)" (Appendix B.4a).
- Real-world validation is a single task with open-loop sim-to-real playback, not closed-loop
  transfer or a broad hardware study: "a more thorough real world investigation of our ideas...
  is outside the scope of this paper" (Sec. V-D).
- Policies retain "multiple imperfections (e.g. large forces)" despite plausible qualitative
  motion (Sec. V-A).

## Quotable claims (verbatim, with section)
- "Even though PGDM uses no hand supervision outside of pre-grasps, we note that the final
  policies often produce smooth motions and realistic finger behavior. This defies conventional
  wisdom in the field that suggests human supervision is critical for 'normal' behaviors"
  (Sec. V-A).
- "these hand trajectories are not used in our method, but are required for the baselines"
  (Appendix B.2, on GRAB data).
- "moving the hand away from the object dramatically reduces PGDM's performance... removing the
  pre-grasp's finger pose causes a drastic decrease in performance" (Sec. V-C).
- "pre-grasps are not stable grasps. In fact, the hand does not make contact with the objects at
  all!" (Fig. 7 caption).
- "we are able to successfully lift the cracker-box object using the actions optimized in
  simulation. No real world adaptation or fine-tuning was required to make this possible"
  (Appendix E).

## Notes for the survey
Sits at the edge of this batch's scope: PGDM/TCDM is not primarily a "learn from human video"
method — its RL reward comes entirely from an OBJECT trajectory (80% GRAB-sourced, 20% synthetic
animator/expert-policy), and human hand information is used only as a single-frame
initialization (pre-grasp), explicitly discarded as a reward/imitation target ("not used in our
method"). This makes it a useful negative control for the survey's "how much does the human hand
signal matter" question: Table II's ablation shows the SINGLE PRE-GRASP FRAME (not a full hand
trajectory) already accounts for most of the performance gap (75.5% default vs 23.1% with an
open-hand pre-grasp) — a much larger swing than most reward-shaping ablations in this batch,
though it is a within-method ablation of the pre-grasp itself, not an embodiment-mapping-quality
ablation (GRAB MoCap hand pose IK'd to 3 different robot hands is never itself varied/measured
for retargeting error). Real-robot evidence is a single unquantified qualitative demo, weaker
than videodex_2022's or cyberdemo_2024's trial-counted real results. Block D: physical
plausibility of the extracted hand-object interaction is not checked via any interpenetration or
contact-quality metric — pre-grasps are defined by construction to avoid contact, and the paper's
only qualitative plausibility claim is that learned policies "produce smooth motions and
realistic finger behavior" (visual/qualitative, not measured) plus the real-hardware
lift succeeding without adaptation.
