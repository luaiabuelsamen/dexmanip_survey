# dexteritygen_2025 — DexterityGen: Foundation Controller for Unprecedented Dexterity (Yin, Wang, Pineda, Hogan, Bodduluri, Sharma, Lancaster, Prasad, Kalakrishnan, Malik, Lambeta, Wu, Abbeel, Mukadam; RSS 2025)

sources: papers/md/dexteritygen_2025.md [sha 8658ddb9] ; no code

## One-line contribution
An RL-pretrained diffusion "foundation controller" (DexGen), trained on 1e10 simulated grasp-to-grasp transitions, takes a coarse/noisy motion command (from human teleoperation or any external policy) and projects it via gradient-guided diffusion sampling onto a safe, high-likelihood low-level action, boosting real-world teleoperated object-holding stability 10-100x and enabling human teleoperators to perform screwdriver/syringe tool-use for the first time.

## Setting
- hand(s): Allegro Hand (16-DoF action space, per Sec. III-D)
  - arm: Franka Panda
  - single/bimanual: single-hand.
    - Human teleoperator's hand tracked with a Manus Glove (retargeted to Allegro at 300 Hz via an unreleased "confidential fast retargeting method") plus a Vive tracker for 6D wrist pose, driving the arm separately.
- simulator / physics: RL pretraining and the Anygrasp-to-Anygrasp dataset generation run in simulation (engine not named in the parsed text)
  - robot assumed driven by a PD controller: torque τ = K_p(q̃_t − q_t) − K_d·q̇_t with scalar gains K_p, K_d, commanding joint target position q̃_t.
- observation: robot state o = stack of historical proprioception
  - the "motion" intermediate representation is 3D finger keypoint offsets Δx ∈ R^{T×K×3} in the hand frame (T = future horizon, K = number of finger keypoints), used because it integrates naturally with human teleoperation guidance signals.
- action space: executable robot action a_t = q̃_t (target joint position), produced by an inverse-dynamics model that maps the diffusion model's predicted keypoint motion to joint targets
  - DDIM sampler used at inference at 10 Hz control, ~27 ms (37 Hz) total sampling time on an RTX 4090.
- objects / data: pretraining dataset = 1×10^10 transitions ("equivalent to 31.7 years of real world experience"), generated by rolling out trained RL policies at a cost of 300 GPU-hours
  - per-object grasp sets sampled with >100K grasps per object during grasp generation (Sec. III-B).
    - Real-world evaluation objects: a diverse held-out set of sizes/masses/aspect-ratios not present in pretraining (Fig. 7)
  - tools used: screwdriver, syringe, pen.

## Method
- paradigm: RL (for dataset generation of low-level motion primitives) + generative pretraining (diffusion model) + guided-sampling inference conditioned on an external (human teleoperation or policy) command — a hybrid "RL data -> IL/generative foundation model -> test-time guidance" pipeline, not end-to-end RL or end-to-end IL.
- algorithm: (1) Data collection: "Anygrasp-to-Anygrasp" RL task — for each object, a candidate grasp set (hand joint position, object pose) is built via Grasp Analysis + RRT (Manipulation-RRT-style)
  - RL rollouts start from a random grasp and are given a goal = a nearby grasp found by k-NN search (goal updated once reached), on the premise that reaching a distant grasp directly is too hard
  - wrist pose and object geometry/physical properties are domain-randomized during training. (2) Model: a UNet-based DDPM diffusion model p_θ(Δx|o) generates keypoint-motion sequences conditioned on state o and a one-hot "mode" conditioning variable (mostly "default"; only a special "precision rotation" mode label is used for the screwdriver task) — trained with the standard diffusion loss
  - a residual-MLP inverse-dynamics model separately converts predicted keypoint motion to joint-target actions, trained with MSE regression loss to a Normal output distribution.
    - Both trained jointly on the simulation dataset with AdamW, 15 epochs, 96 GPUs, ~3 days (Sec. III-C).
- key trick(s): guided diffusion sampling for motion conditioning — sample Δx ~ p_θ(Δx|o)·exp(−Dist(Δx, Δx_input)), implemented by subtracting a gradient correction α·Σ·∇_Δx Dist(Δx, Δx_input) at each reverse-diffusion step (α a tunable guidance-strength hyperparameter), where Δx_input is the externally commanded fingertip offset — this "projects" a dangerous/coarse external command onto the nearest safe, high-likelihood action from the learned distribution rather than executing it directly (Sec. III-D).
  - Disabling the DexGen controller entirely is used as the mechanism for "releasing" an object, since the training data is dominated by grasp-holding transitions.
- Reward/objective: no task reward is quoted (this is not a reward-shaped RL-for-task paper)
  - the RL reward used to train the underlying Anygrasp-to-Anygrasp primitive policies is not given in the parsed body text (Appendix mentions "Net Force Optimization" and diverse-reward "boosting" but the reward formula itself is not quoted in the parsed sections read).

## Evaluation
- metrics: simulation — average trial duration (seconds, object not dropped) and number of achieved grasp goals over a 20-minute simulated rollout, for noise-corrupted expert policies π_noisy = π_exp(a|s) + U(−α,α) and π_slow = U(0,α)·π_exp(a|s), compared to DexGen∘π.
  - Real-world — success rate (SR, fraction of trials) and time-to-fall/holding-time (TTF, normalized by episode length) per task (Table I)
  - breakdown stage-wise success counts for long-horizon tasks (Table II).
- headline numbers: "boost the duration by 10-100x" for noisy/slow expert policies wrapped with DexGen in simulation (Fig. 8, qualitative plot, no single scalar table in parsed text).
  - Real-world (Table I, 2 users, 30-min familiarization per system): Reorient Large(Up) — Teleop 0/20 SR (<5% TTF) vs.
  - Teleop+DexGen 12/20 SR (75% TTF)
  - Reorient Small(Up) 0/20 vs 13/20 (79%)
  - Reorient Large(Down) 0/20 vs 10/20 (63%)
  - Reorient Small(Down) 0/20 vs 9/20 (58%)
  - Func Grasp 0/10 vs 7/10 (87%)
  - Func Grasp(Horizontal) 1/10 vs 6/10 (80%)
  - Regrasp(Ball) 0/10 vs 5/10 (78%)
  - Regrasp(Cylinder) 0/10 vs 5/10 (74%).
    - Long-horizon breakdown (Table II, out of 20 attempts): Screwdriver stages Reorient 16/20 → Regrasp 11/20 → Align 5/20 → Use 3/20
  - Syringe stages Reorient 15/20 → Regrasp 9/20 → (Align not listed) → Use 4/20 — success rate falls off sharply as more sequential stages are chained.
- baselines beaten: raw human teleoperation with no DexGen assistance (fails almost completely on every real-world task, 0/20 or near-0 in most cells).

## Limitations stated by the authors
The pretraining dataset, while large (1e10 transitions / 300 GPU-hours), is hypothesized to still be "far from sufficient as human dexterity emerges from millions of years of evolution" (Sec. III-B) — i.e., the authors flag their own scale as likely insufficient rather than saturating. Long-horizon tool-use tasks (screwdriver, syringe) remain challenging: stage-wise success is reasonable but chaining stages together (Reorient→Regrasp→Align→Use) degrades sharply (e.g. screwdriver "Use" stage only 3/20), which the authors attribute to needing improved stage-wise policy performance, deferred to future work (Sec. IV-D, referencing the conclusion).

## Quotable claims (verbatim, with section)
- "significantly improves stability by 10-100x measured as duration of holding objects across diverse tasks" (Abstract).
- "We collect a total of 1×10^10 transitions as our simulation dataset, equivalent to 31.7 years of real world experience.
  - Generating this dataset... requires 300 GPU hours.
  - Although the dataset is large, we hypothesize it can still be far from sufficient as the human dexterity emerges from millions of years of evolution" (Sec. III-B).
- "The raw teleoperation baseline fails completely on those tasks, while our method can help the teleoperation policy to achieve both stability and success in diverse setups" (Table I caption).
- "We find that the fingertips show some 'magnetic effect' when they are in contact with the object.
  - When the user mistakenly moves a supporting finger which may drop the object, our model can override that behavior and maintain the contact as if the fingertips are sticking to the object" (Sec. IV-D).

## Notes for the survey (which sections this feeds; contradictions with other notes)
This is the odd one out among the batch: it is not primarily a data-scaling paper (data is 100% RL rollouts in simulation, not human motion or demonstrations) but a "shared-autonomy / assistive low-level controller" paper — feeds the survey's "teleoperation quality via a learned safety layer" section alongside teledexter_2026 and dexteleop0_2026, contrasted against dexwild_2025/dexumi_2025/dexcap_2024 which are pure data-collection-then-BC pipelines. Its "1e10 transitions, 31.7 years of experience" framing is a useful scale anchor when the survey compares simulated-RL-data volume against DexTrack's own frame-count stop rule and against Dex1B's 950M synthetic poses (dex1b_2025) — note both papers report huge simulated-only datasets but for different purposes (motion-primitive pretraining for guidance vs. grasp-pose generation for BC). No hand-object interpenetration or contact-force measurement is reported; "safety" in this paper means not dropping the object (holding-time/TTF), not penetration or force limits — flag this distinction when cross-referencing against opposition-deficit's own interpenetration metric conventions.
