# dexgraspvla_2025 — DexGraspVLA: A Vision-Language-Action Framework Towards General Dexterous Grasping (Zhong et al., arXiv 2025)

sources: papers/md/dexgraspvla_2025.md [sha256 dbd34b75] ; code/md/dexgraspvla_2025.md [commit 0144c792]

## One-line contribution
A hierarchical VLA — frozen VLM planner (bounding-box affordance) + diffusion-policy controller on frozen DINOv2 features — trained purely by real-world imitation learning, reaching 90.8% aggregated zero-shot grasp success across 1,287 unseen object/light/background combinations (Table 1c).

## Setting
- hand(s): PsiBot G0-R, 6-DoF, single (right) hand ; arm: RealMan RM75-6F, 7-DoF ; single/bimanual: single-arm/single-hand ("Hardware Platform," Sec. 5.1: "our setup includes a 7-DoF RealMan RM75-6F arm and a 6-DoF PsiBot G0-R hand")
- simulator / physics: none — real-robot only, no simulation reported anywhere in the paper or code
- observation: head camera image (RealSense D435, 3rd-person), wrist camera image (RealSense D405C, 1st-person), both 640×480×3; object binary mask **m**_t (640×480×1, from SAM+Cutie tracking); proprioception **s**_t ∈ R^13 (arm 7 + hand 6) (Sec. 3, Sec. 4.1, Sec. A.1)
- action space: joint position targets, **a**_t = (**a**_t^arm ∈ R^7, **a**_t^hand ∈ R^6) ∈ R^13; predicted as a chunk of horizon H=64 via diffusion, executes first 6 before replanning; control rate 20 Hz (Sec. 3, Sec. A.1, Sec. A.3: "The control frequency is 20Hz")
- objects / data: 2,094 successful kinesthetic-teaching demonstrations over 36 household objects for the main grasping controller (Sec. 4.2); a separate nonprehensile controller trained on 1,029 demonstrations over 32 flat/wide objects (Sec. 5.7). Each grasping episode fixed at 75 timesteps; each demo ~3.5s (Sec. 4.2, Sec. A.3). Evaluation object pool: 360 unseen objects, 6 unseen backgrounds, 3 unseen lighting conditions (Sec. 5.2)

## Method
- paradigm: VLA — frozen pretrained VLM planner (no fine-tuning stated) + imitation-learned diffusion-policy controller (IL, not RL); no distillation, no privileged-to-vision transfer
- backbone VLM: Qwen-VL-Chat (Bai et al. 2023) used as the default planner for all experiments except long-horizon; Qwen2.5-VL-72B-Instruct used for the long-horizon task (Sec. 5.1: "the high-level planner is based on Qwen-VLChat ... except in the long-horizon task ... where we use Qwen2.5-VL-72B-Instruct"). Parameter count is stated only for the long-horizon variant: 72B ("Qwen2.5-VL-72B-Instruct"). Qwen-VL-Chat's parameter count is **not stated** in the paper.
- action head — quoted formulation (Sec. 4.1): "For action prediction, we employ a DiT (Peebles and Xie 2023) to generate multi-step actions, following the diffusion policy paradigm (Chi et al. 2023; Liu et al. 2024)... a random diffusion step t_d = k is sampled, and Gaussian noise ε is added to A_t, yielding the noised action tokens x_k = α_k A_t + σ_k ε... We then feed x_k into the DiT alongside the observation feature sequence z̃^obs_t. Each DiT layer performs bidirectional self-attention over the action tokens, cross-attention to z̃^obs_t, and MLP transformations, ultimately predicting the original noise ε. By minimizing the noise prediction error, the model learns to reconstruct the ground-truth action chunk A_t." Noise is added via **Immiscible Diffusion** (Li et al. 2024) rather than plain DDPM noising ("we employ Immiscible Diffusion... to improve data-noise mapping," Sec. A.1); inference uses DDIM sampling with 16 inference steps out of 50 training timesteps (Table 2).
- action chunk length / control rate: H = 64 (action chunk horizon), receding-horizon execution of the first 6 actions per prediction; control frequency 20 Hz (Sec. 4.1, Sec. A.1, Table 2 "action horizon: 64")
- fine-tuning recipe: none for the VLM planner — it is used off-the-shelf/frozen, queried via API or self-hosted vLLM ("we adopt an off-the-shelf pre-trained Qwen VLM... as a high-level planner," Sec. 4.1; deployment via vLLM 0.7.3, Sec. code-md "DexGraspVLA Planner"). The controller (DiT + fusion MLPs + mask ViT) is trained **end-to-end from scratch** by imitation learning on the 2,094-demo dataset — this is not a fine-tune of a pretrained action-generalist VLA. DINOv2 encoders are frozen (kept off in the ablations "DINOv2-train" and replaced in "ViT-small").
- key trick(s): domain-invariant intermediate representations — a VLM-predicted bounding box → SAM initial mask → Cutie mask tracking (m_t) as a stable affordance signal, and frozen DINOv2 (ViT-B/14 head, ViT-L/14 wrist) features as visually-invariant scene representations, so the IL controller trains on representations that stay consistent despite domain-varying pixels (Sec. 4.1).

- observation vector as fused by the controller (Sec. A.1): head features z^h_t ∈ R^1369×768 (DINOv2 ViT-B/14 on 518×518 resized head image), wrist features z^w_t ∈ R^1369×1024 (DINOv2 ViT-L/14), mask features z^m_t ∈ R^1369×768 (randomly-initialized ViT on m_t), patch-wise concat of z^h_t and z^m_t → z̄^h_t ∈ R^1369×1536, then separate MLPs project z̄^h_t, z^w_t, s_t into a common 1024-dim space and concatenate into z̃^obs_t ∈ R^2739×1024. Diffusion timestep embedding z̃^d_t ∈ R^1×1024 is appended to form the DiT condition sequence z̃_t ∈ R^2740×1024.
- domain randomisation: color jittering applied to images during training before DINOv2 normalization ("we apply domain randomization via color jittering," Sec. A.1) — no other randomized quantity (mass, friction, lighting-in-sim, etc.) is stated, consistent with there being no simulator.

## Reward / objective block
- Problem is formalized with a binary task reward (Sec. 3): "The robot receives a binary reward r ∈ {0, 1} indicating whether it has completed the instruction l successfully. The goal of the policy π is to maximize the expected reward E[r]." This reward is **not used for training** — the controller is trained purely by imitation (diffusion loss below); the binary reward is only the formal objective the eval metric approximates.
- Training loss (Sec. 4.1, verbatim): "During training, we compute MSE loss between the noise prediction and ground truth, and back-propagate the gradient to update all trainable parameters." No auxiliary loss terms, no weighting scheme, and no reward-shaping terms are given anywhere in the paper. From code/md `controller/policy/dexgraspvla_controller.py`, the loss is computed by `compute_loss(self, batch, training)` inside `DexGraspVLAController(BaseImagePolicy)`, and noise is produced by a separate top-level function `noise_assignment(data, noise)` (Immiscible Diffusion pairing) — **only function signatures are present in code/md/dexgraspvla_2025.md, not the loss body**, so the exact code-level loss expression cannot be quoted; the paper's prose statement above is the only available formulation.
- Action chunking / horizon (IL): chunk A_t = a_{t:t+H} with H = 64, receding-horizon execution of Ha = 6 actions before replanning (Sec. 4.1, "the controller executes the first six actions in the predicted action chunk before making a new prediction").

## Contact / penetration handling
Not addressed. Neither "penetration," "contact," nor "collision" (outside a bibliography title) appears anywhere in the paper body, and there is no simulator in this work (real hardware only), so no contact solver settings exist to report.

## Evaluation
- metrics (exact definitions): "A grasp is successful if the object is held 10 cm above the table for 20 s. Success rate is the ratio of successes to total tests; aggregated performance is a weighted average by task proportion." (Sec. 5.2). Long-horizon task success = "the proportion of tests that fully complete all required stages" (Sec. 5.6).
- headline numbers, large-scale generalization (Table 1c): Ours@1 — 91.1% on 360 unseen objects, 90.5% on 6 unseen backgrounds (618 tests), 90.9% on 3 unseen lightings (309 tests), 90.8% aggregated. Ours@2 = 94.7% aggregated, Ours@3 = 96.9% aggregated (up to 3 attempts allowed).
- baseline comparison (Table 1a, smaller-scale: 24 unseen objects, 2 unseen backgrounds, 2 unseen lightings, 12 seen objects): Ours 91.7%/91.7%/89.6%/93.8% (seen/unseen-obj/unseen-bg/unseen-light) = 91.7% aggregated, vs. π0 (Full FT) 75.0%/45.8%/20.8%/20.8% = 30.3% aggr; π0 (LoRA) 58.3%/45.8%/14.6%/10.4% = 22.7% aggr; RDT (Full FT) 25.0%/25.0%/31.3%/35.4% = 31.1% aggr; OpenVLA-OFT (LoRA) 25.0%/29.2%/31.3%/31.3% = 30.3% aggr; OpenVLA (LoRA) 33.3%/16.7%/14.6%/4.2% = 12.9% aggr.
- ablation, single-object grasping (Table 1d, 210 tests: 13 seen + 8 unseen objects × 5 locations × 2 trials): Ours 98.5% seen / 98.8% unseen / 98.6% aggr, vs. ViT-small 60.0%/35.0%/50.5%, DINOv2-train 30.0%/43.5%/34.8%.
- long-horizon (Table 1b, 24 scenes/prompt, 4 prompts): task success 95.8% (Clear Table), 87.5% (Grasp Green), 91.7% (Grasp Bottles), 83.3% (Grasp Food), 89.6% aggregated; planner instruction-proposal 94.3% aggr, bbox accuracy 98.4% aggr, controller grasping 92.2% aggr, planner completion-check 96.3% aggr.
- nonprehensile extension (Table 1e, 36+36+72 = 144 tests): Ours 88.9% unseen objects / 86.1% unseen backgrounds / 77.8% unseen lighting / 84.7% aggr, vs. DINOv2-train 66.0% aggr, ViT-small 39.6% aggr.
- baselines beaten: π0 (Full FT & LoRA), RDT (Full FT), OpenVLA (LoRA), OpenVLA-OFT (LoRA) — all fine-tuned on DexGraspVLA's own demonstration dataset (Sec. 5.1, Sec. A.2), not quoted from their original papers.
- real robot? Yes — all reported numbers are real-robot (no simulation exists in this work). Trial counts given per condition above (e.g., 360/618/309 for Table 1c; 210 for Table 1d; 24×4=96 for Table 1b; 144 for Table 1e).
- eval episodes/seeds: not stated as RNG seeds (training uses `seed: 42` per Table 2/config, but evaluation trial counts are fixed test-scene counts, not seeded sim rollouts).

## Limitations stated by the authors
"While effective, it does not yet address functional grasping and subsequent manipulation, nor does it incorporate tactile sensing. In future work, we aim to extend the high-level planner to generate more fine-grained affordance and learn a task-oriented manipulation controller that also integrates tactile feedback." (Sec. 6)

## Quotable claims (verbatim, with section)
- "DexGraspVLA achieves an unprecedented 90.8% success rate for grasping in cluttered scenes spanning 1,287 unseen object, lighting, and background combinations, all tested in a 'zero-shot' environment." (Sec. 1)
- "In total, the controller possesses 163M trainable parameters." (Sec. A.1) — note this is the trainable fusion-MLP + mask-ViT + DiT parameter count with DINOv2 and the VLM frozen, not the size of the full system.
- "We train the controller for 84 epochs over our dataset on an 8-A800 GPU server, which takes less than one day to complete." (Sec. A.1)
- "our model takes around 6 s to grasp an object, which is close to that of humans." (Sec. 5.2)

## Notes for the survey (which sections this feeds; contradictions with other notes)
- Confirms this is a genuine dexterous-hand (6-DoF, PsiBot G0-R) result, not a parallel-jaw gripper dressed up as "dexterous" — feeds the survey's embodiment table directly.
- The 163M "trainable parameters" figure is easy to misquote as "the whole model size"; the VLM planner (72B for the long-horizon variant, unstated for the default Qwen-VL-Chat) and the frozen DINOv2 encoders are excluded from that count. Flag this distinction wherever total compute/param comparisons are made across papers in the survey.
- Only function signatures were available in code/md/dexgraspvla_2025.md for `dexgraspvla_controller.py`; the actual MSE/Immiscible-Diffusion loss body could not be verified against the paper's prose description — treat the loss formulation here as paper-only, not code-verified. Hardware-interfacing code is explicitly withheld ("Due to intellectual property constraints, we are unable to open-source the hardware-related code," code/md "DexGraspVLA Inference").
- Table 1 is badly flattened in the PDF→markdown conversion (columns interleave across sub-tables 1a–1e); numbers above were reconstructed by cross-checking against the prose restating of each number in Sec. 5.2–5.7, which all matched exactly.
