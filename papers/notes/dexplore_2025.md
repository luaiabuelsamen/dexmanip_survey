## One-line contribution
A single-loop RL policy treats MoCap hand-object references as soft guidance rather than ground truth: reward-matching weights and early-termination thresholds ("reference scopes") are derived adaptively from the reference and from training progress, letting one optimization jointly perform retargeting and tracking without an explicit correspondence-optimization stage or residual-correction stage, then distills the result into a vision-based, skill-conditioned generative controller for real deployment (Abstract; Sec. 3).

## Setting
- hand(s): Inspire hand (12 DoF, 6 actuated, mimic joints simulated) and Allegro hand (16 DoF, fully actuated, larger than a human hand) reported in the paper (Sec. 4, "Data and Robot Models"); code also ships Leap and Shadow hand task variants (dexplore/env/tasks/dexplore_{inspire,allegro,leap,shadow}.py) not evaluated in the paper. Floating 6-DoF wrist root + local finger joints; single-hand only (bimanual explicitly out of scope, Sec. 6 Limitations).
- simulator / physics: Isaac Gym [63] (Table A). Sim timestep 1/60s, control timestep 1/30s, 4096 parallel environments, 8 physics substeps, 8 position solver iterations, 1 velocity solver iteration, contact offset 0.02, rest offset 0.0, max depenetration velocity 10, object restitution 0.7, friction 0.9, density 50 (App. B, Table A).
- observation: proprioceptive+privileged state x_t = hand kinematics {R^h_t, J^h_t, ω^h_t, v^h_t} (joint rotations/positions/angular+linear vel), object state {R^o_t, p^o_t, ω^o_t, v^o_t}, plus two sensory modalities following [51]: D_t (vectors from each hand joint to nearest object surface point) and C_t (binary per-rigid-body contact indicators, "mimicking tactile sensing") (Sec. 3.1, "State"). Goal component x̂_t is the same feature set computed from the MANO reference at future indices {t+k}_{k∈K}, expressed as deltas via a correspondence mapping M that projects robot and MANO skeletons onto a shared key-joint subset — for the Inspire hand "the mapping simplifies to the five fingertips" (Sec. 3.1). Vision-distilled student observes hand proprioception + an object point cloud from a single-view depth image (PointNet++ backbone), short-horizon history, and a before/after-manipulation-onset binary flag; joint velocities and tactile are excluded "due to their large sim-to-real gap" (Sec. 3.2).
- action space: PD targets split into a 6-DoF floating-wrist signal (exponential-map rotation) and local finger commands; wrist control is residual — "a 6-DoF positional offset is added to the current wrist state to form the PD target" (Sec. 3.1). Mimic joints (e.g. Inspire) have their PD target scaled by a predefined coupling coefficient to reproduce the hardware linkage.
- objects / data: GRAB [60], 658 sequences / 51 objects selected from 1,269 original sequences, filtered to single-hand (mostly right-hand) manipulation only (Sec. 4). Generalization also evaluated (qualitatively) on the TACO dataset [64] (objects 081, 194) without retraining, for both the state-based policy and the vision-distilled policy (Sec. 4, Fig. C).

## Method
- paradigm: RL (state-based teacher, PPO) + IL/distillation (vision-based student via DAgger from the teacher). Algorithm: PPO [50] for Sec. 3.1's tracker; DAgger-style online imitation with a VAE-like encoder/prior/decoder for Sec. 3.2's generative controller.
- human dataset retargeting: explicitly NOT retargeting-then-tracking. The framework "does not require explicit retargeting" (Sec. 4) — instead, MANO reference states are related to the robot via the mapping M used only to compute reward/observation deltas over a shared key-joint subset (5 fingertips for Inspire), "analogous to the correspondence used in retargeting objectives," adopting the mapping from AnyTeleop [33] (Sec. 3.1, "State"). No separate optimization stage produces retargeted robot joint angles as training targets; the robot state is only initialized from the reference's global wrist pose (all other DoF set to zero), then RL free-explores from cached high-quality rollout states with prioritized sampling toward harder phases (Sec. 3.1, "State Initialization").
- reward (paper, Sec. 3.1, quoted): total reward = R_match(x_t, x̂_t) + R_energy(a_t). R_match combines kinematic hand-joint rotation/position matching (R_R^h, R_J^h), object orientation/position matching (R_R^o, R_p^o), and coarse geometric/contact correspondence (R_D, R_C). Exact forms: R_J^h = exp(−λ^h_J‖M(p̂)−M(p)‖²), R_R^h = exp(−λ^h_R‖M(R̂)⊖M(R)‖²), R_D = exp(−λ_D‖D̂−D‖²), R_C = exp(−λ_C‖Ĉ−C‖²) (object R_R^o/R_p^o are stated as analogous but not written out explicitly). R_energy penalizes large consecutive PD-target changes plus high joint accelerations/velocities. Reference-scope weighting: kinematic weight w(D) = min(1, 0.20/D[m]) — i.e. λ^h_R and λ^h_J scale with this factor, proportional to hand-object surface distance, while the energy penalty is inversely proportional to it, "encouraging smoother, lower-energy motions when tracking constraints are relaxed" (Sec. 3.1, "Learning with Reference Scope").
- reward (code): `compute_humanoid_reward` in base_dexplore_task.py takes params (hoi_ref, hoi_obs, contact_buf, tar_contact_forces, len_keypos, w, pos_actions, actions, object_points, object_pos_action, object_rot_action, num_dof, ball_size, t_sat, kappa) confirming the paper's described inputs (a weight dict `w`, a `kappa` termination-threshold argument, `t_sat` presumably the saturation/scope-tightening schedule) and a `huber_loss(diff, sigma)` helper is defined alongside it — but the function body (the actual per-term weighted sum) is not present in the parsed code md, so the exact numeric constants cannot be independently verified against the paper's formulas. SOURCE THIN FOR REWARD BLOCK on the code side only: paper gives the formulas and the w(D) schedule; code confirms the same argument structure exists (w, kappa, t_sat) but not the literal weight values λ^h_R, λ^h_J, λ_D, λ_C.
- Early Termination / "reference scope" (paper, Sec. 3.1, quoted verbatim): "(I) R_J^h < κ^h_J, (II) R_p^o < κ^o_p, (III) R_R^o < κ^o_R, (IV) R_D < κ_D, (V) C_t ≠ Ĉ_t, ∀t ∈ [t0, t0+10]" — i.e. reward-based (not raw-distance) thresholds on hand-joint position tracking, object position tracking, object rotation tracking, geometric/contact correspondence, and a 10-step window of contact-label mismatch. Thresholds are adaptive: κ = κ_init · N_fail/N_total, tightening as the rollout success rate improves — "wide envelopes" early in training, progressively tightened. This IS the paper's central "reference-scoped exploration" (RSE) mechanism.
- key trick(s): reference-scoped adaptive early termination in place of hard tracking reward (ablated as "DEXPLORE w/o RSE" in Table 1, showing a large success-rate drop); residual wrist action space; prioritized state initialization from cached successful rollouts; a latent skill-conditioned decoder (encoder q_φ(z|x,x̂), prior p_ψ(z|x̃,P), decoder π̃_θ) trained with L = L_rec + βL_KL (L_rec = ‖a−ã‖², L_KL = KL(N(μ_p+μ_q,Σ_q)‖N(μ_p,Σ_p))) for the vision-based student, with noise ϵ held fixed within an episode for temporally consistent skills (Sec. 3.2).

## Evaluation
- metrics (Sec. 4, "Metrics"): Object Rotation Error (R_err, per-frame orientation discrepancy, radians per Table 1 units); Object Translation Error (T_err, per-frame position discrepancy, reported in cm); Fingertip Error (E_finger, average per-frame fingertip positional difference, cm); Success Rate — "proportion of tracking attempts completed without dropping the object or exhibiting large deviations as indicated by the aforementioned metrics" (i.e. success is tied to the same reward-based reference-scope criteria used for termination, not a separately stated numeric threshold). Vision-based policy: Success Rate (stable hand-object contact over a duration + object returned to table) and Contact Ratio (fraction of time in contact) (Sec. 4).
- headline numbers (Table 1, GRAB, values reported as successful-rollouts-avg / all-frames-avg): Inspire hand — DEXPLORE R_err 0.474/0.452 rad, T_err 3.77/3.65 cm, E_finger 6.06/6.04 cm, Success Rate 87.7%; DexTrack w/ AnyTeleop retargeting Success Rate 7.4%; DexTrack w/ DEXPLORE-as-retargeting Success Rate 69.8%; DEXPLORE w/o RSE Success Rate 29.9%. Allegro hand — DEXPLORE Success Rate 78.7% vs. DexTrack w/ AnyTeleop 45.9%, DexTrack w/ DEXPLORE-retargeting 77.4%, DEXPLORE w/o RSE 29.9%.
- baselines beaten: AnyTeleop [33] (pure kinematic retargeting, "task-unaware," fails on low-DoF hands per Fig. 3 qualitative comparison); DexTrack [9] (re-adapted, since "DexTrack's primary contributions, including homotopy optimization and the combination of IL and RL, have not been publicly released" — the paper explicitly flags this as a partial/adapted reimplementation, not the original DexTrack system); ablation DEXPLORE w/o RSE (hard/rigid tracking reward instead of adaptive scope).
- real robot? yes — XArm-7 + Inspire RH56DFTP right hand (12 joints, 6 actuated + 6 mimic), Femto Bolt depth camera, position control gains set explicitly in sim (Kp=100, Kd=10) but the real robot "employs internally defined position control parameters" (App. C). No explicit trial-count/success-rate table for real-world runs is given in the parsed text beyond qualitative claims of "successful examples" (Sec. 4, Figs. 5/A) — real-world quantitative success rate is NOT reported as a number in the parsed sections.

## Limitations stated by the authors (Sec. 6)
- "sometimes struggles with reliably manipulating very small or thin objects, where slight inaccuracies in fingertip positioning significantly affect success."
- Single-hand interactions only; multi-hand coordination "requires further exploration."
- Training dataset (658 GRAB sequences) is "relatively modest, limiting generalization."

## Quotable claims (verbatim, with section)
- "Rather than treating demonstrations as ground truth, we use them as soft guidance. From raw trajectories, we derive adaptive spatial scopes, and train with reinforcement learning to keep the policy in-scope" (Abstract)
- "the kinematic weight is given by w(D) = min(1, 0.20/D[m])" (Sec. 3.1, "Learning with Reference Scope" — D in metres)
- "κ = κ_init · N_fail/N_total, where κ_init is the initial large threshold, N_fail is the number of unsuccessful rollouts... and N_total is the total number of rollouts visited at the current frame." (Sec. 3.1)
- "retargeting errors can propagate and bias downstream learning, for example, a grasp that is feasible for a human may be infeasible or strongly suboptimal for a robotic hand" (Sec. 1)
- "Our framework does not require explicit retargeting; however, we evaluate retargeting algorithms separately for comparison purposes." (Sec. 4)

## Notes for the survey
- Feeds: the retargeting-taxonomy section as the strongest "soft-guidance, no explicit correspondence-optimization" design point, contrasted directly against objdex_2024 (wrist-only retargeting + RL fingers) and dexmachina_2025/toporetarget_2026 (explicit kinematic retargeting stage). DEXPLORE keeps a lightweight correspondence map M (shared key joints, e.g. 5 fingertips for Inspire) purely inside the reward/observation, never producing a retargeted trajectory as a supervised target — a third point on the spectrum between "no correspondence at all" (physhoi_2023, omnigrasp_2024, same-embodiment humanoid) and "explicit IK/optimization retargeting" (most other notes in this batch).
- Object tracking: position AND orientation, both in the reward (R_p^o, R_R^o) and in termination criteria (κ^o_p, κ^o_R) and in reported metrics (T_err, R_err) — a genuine 6-DoF-tracked method per Sec. 3.1's task formulation ("full 6-DoF poses (position and orientation)").
- Failure/termination definition: unusual among this batch — termination is defined on REWARD values falling below adaptive thresholds (κ), not on raw distance/angle thresholds; the five criteria (I)-(V) in Sec. 3.1 include a contact-mismatch condition sustained for a 10-step window, which is the paper's only quantized time constant for termination.
- Block D (interpenetration): not measured or penalized as a reward/metric term — the paper's contact signal (C_t, binary contact indicators, "tactile"-like) rewards CORRECT presence/absence of contact against the reference (R_C term, analogous to physhoi_2023's contact-graph reward and omnigrasp_2024's contact-filter gate), not absence of penetration. The only interpenetration-adjacent numbers are Isaac Gym PhysX solver settings in Table A: contact offset 0.02, rest offset 0.0, max depenetration velocity 10 — these are simulator collision-response parameters, not a measured or reported penetration statistic on rollouts. No interpenetration metric appears in Table 1, Table B, or anywhere in the text; treat as "not addressed" beyond generic solver configuration.
- Cross-reference: Table 1's DexTrack-as-baseline numbers (Success Rate 7.4-45.9% depending on retargeting source) should be read cautiously in the survey per the paper's own caveat that DexTrack's IL/RL combination and homotopy optimization "have not been publicly released" — these are a re-adapted approximation of DexTrack, not the original system's reported numbers, and should not be conflated with whatever dextrack_2025.md's own headline numbers say.
