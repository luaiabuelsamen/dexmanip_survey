# maniskill3_2024 — ManiSkill3: GPU Parallelized Robotics Simulation and Rendering for Generalizable Embodied AI (Tao et al., RSS 2025; arXiv 2410.00425)

sources: papers/md/maniskill3_2024.md [sha256 0482cef4] ; code/md/maniskill3_2024.md [commit 62ff3a58]

## One-line contribution
Open-source (Apache-2.0) SAPIEN/PhysX simulator with GPU-parallel simulation *and* rasterised rendering, heterogeneous per-env scenes, 12 task categories and 20+ robots, plus RL/IL baselines and sim2real/real2sim digital twins; claims "up to 30,000+ FPS" sim+render and 2-3x lower GPU memory than Isaac Lab (Abstract, Sec. I contribution 1).

## Setting
- hand(s): the paper names no hand in the main text; the dexterous category is described only as "tasks often involving multifingered hands" with an in-hand rotation example (App. VII-H, Fig. 22) and "touch sensors placed on the dextrous hand at various points" (App. VII-H). Hands appear by name only in the VR-teleoperation figure: "a floating Delto 3-finger hand, XArm7 with Inspire hand, dual XArm7 with Ability hand, a floating Allegro hand" (Fig. 39 caption, App. XII). Code has agent classes `AllegroHandRight`/`AllegroHandLeft` and `AllegroHandRightTouch` (FSR impulse readout, `get_fsr_impulse`) in `mani_skill/agents/robots/allegro_hand/`, `FloatingAbilityHandRight` in `floating_ability_hand/`, and `FloatingInspireHandRight/Left`, `FixedInspireHandRight/Left` in `inspire_hand/`. DoF counts and vendors are not stated in either source. A TriFinger port (`mani_skill/envs/tasks/rotate_cube.py`, docstring: "Modified from ... IsaacGymEnvs ... trifinger.py") is the only three-finger task.
- arm: Franka Panda, UR5 (App. VII-A); XArm7 in teleop; Koch v1.1 for sim2real (App. VIII-A). single/bimanual: bimanual/humanoid category exists (Unitree H1/G1, App. VII-E; code `humanoid_pick_place.py`, `transport_box.py`), multi-agent two-arm tasks (`two_robot_pick_cube.py`, `two_robot_stack_cube.py`). No bimanual dexterous-hand task is named in either source.
- simulator / physics: SAPIEN with PhysX on GPU ("Both Isaac Lab and ManiSkill3 use PhysX for GPU simulation", Sec. II). Benchmark settings (App. XI-A, verbatim list): "Simulation frequency: 120 / Control frequency: 60 / Solver Position Iterations: 4 / Solver Velocity Iterations: 0"; Fig. 4 caption repeats sim 120 / control 60 ("camera renders ever 2 sim steps"). Per-task defaults live in `_default_sim_config` (signatures only in code md; values not exported). Dependency pin `sapien==3.0.0.b1` in `examples/baselines/tdmpc2/environment.yaml`. GPU sim engaged when `num_envs > 1` (`BaseEnv` docstring, `mani_skill/envs/sapien_env.py`). Soft-body envs are 2-way coupled rigid-MPM from ManiSkill2 and are not batched (App. VII-L, Sec. V).
- observation: state, RGB, depth, segmentation, pointcloud, voxels (Sec. III-B). Dexterity envs add `obj_pose`, `obj_tip_vec` (12-vector), `rotate_dir` (`rotate_single_object_in_hand.py::_get_obs_extra`); valve env adds `valve_qpos/qvel`, cos/sin of valve angle (`rotate_valve.py`).
- action space: prebuilt controllers for "GPU parallelized joint position control and inverse-kinematic (IK) control" via PyTorch Kinematics (Sec. III-F.2); sim2real uses "target delta joint position controller ... at a control frequency of 30Hz", action clipped to [-1,1] then scaled to ±0.05 rad per joint (App. VIII-B).
- objects / data: YCB and PartNet-Mobility for heterogeneous envs (Sec. III-C); ReplicaCAD, AI2-THOR, RoboCasa scenes (App. VII-C); "millions of demonstration frames" from motion planning, RL and teleop (Abstract), teleop sets "typically about 10 demonstrations" then scaled with RFCL/RLPD (Sec. III-G).

## Method
- paradigm: simulator + benchmark; baselines PPO, SAC, TD-MPC2 (wall-time and sample-efficient configs), BC, Diffusion Policy, ACT, PerAct, RLPD, RFCL; eval-only Octo, RT-X, RDT-1B (Sec. IV-A, IV-B).
- reward (dexterous, from code, `mani_skill/envs/tasks/dexterity/rotate_single_object_in_hand.py::compute_dense_reward`, verbatim):
  `reward = 20 * angle` (rotation_angle); `+= -0.1 * obj_vel`; `+= -50.0 * obj_fall`; `+= -0.0003 * power`; `+= -0.0003 * qf_norm`; `distance_rew = 0.1 / (0.02 + 4 * obj_tip_dist); reward += mean(clip(distance_rew, 0, 1))`; normalised by `/ 4.0`. Levels 0-3 exist as subclasses; what differs per level is not in the code md.
  `rotate_valve.py::compute_dense_reward`: `reward = 1 - tanh(error * 10)` (fingertip-to-valve-tip distance error, 3 fingertips), `+= tanh(5 * directed_velocity) * 4`, `+= clip(rotation / pi / 2, -1, 1)`; normalised `/ 6.0`; levels 0-4.
  `rotate_cube.py` (TriFinger): `finger_reach_object_reward = 5 * mean_i(1 - tanh(5 * ||tip_i - obj||))`; `pose_reward = 5 * (object_dist_reward + object_lift_reward) + 5 * (-|quat_diff_rad(obj_q, goal_q)|)`, clamped to [-15, 15], `total_reward[info["success"]] = 15`; normalised `dense/(2*15) + 0.5`; levels 0-4.
  `insert_flower.py`: `reward = exp(-5 * ||max(box_lo - p, 0), max(p - box_hi, 0)||)` (flower position inside a target box).
  Sparse reward default (`sapien_env.py::compute_sparse_reward`): "+1 if success, -1 if fail, 0 otherwise".
  Sim2real PickCube reward (App. VIII-E): indicators I_grasped, I_touch_table, I_tcp_close; `r_dist(x,y,z) = 1 - tanh(z * ||x - y||)`, `r_orient(g) = 1 - (u · g/||g||)`; the equation itself did not survive PDF parsing.
- key trick(s): heterogeneous GPU simulation (different DoF articulations / object counts per env, Sec. III-C); parallel rasterised rendering via SAPIEN (Isaac Lab uses ray tracing, Sec. III-B); green-screening real background + segmentation-mask compositing and per-step camera-pose jitter (±2.5 cm), per-reset joint noise N(q_R, 0.02), per-reconfigure cube size U[1.5, 2.25] cm, friction N(0.3, 0.025), colours (App. VIII-D); partial resets always on for PPO (App. IX-A); `reconfiguration_freq` controls re-sampling of non-resettable properties (App. IX).

## Evaluation
- metrics: success rate per task (`evaluate()` returns `info["success"]`; bodies are not in the code md, so the dexterous success predicates cannot be quoted). Real2sim: correlation and "Mean Maximum Rank Violation (MMRV) (lower the better), which assess the accuracy of the consistency of the rankings of real and sim policy evaluations" (Fig. 25 caption).
- throughput (all on RTX 4090, App. XI-A; cartpole benchmark env, Isaac Lab v1.2.0):
  - sim only: "ManiSkill3 runs a little faster and uses about 1.5x to 2x less GPU memory" (App. XI-B, Fig. 30; Fig. 30 caption: "on par with Isaac Lab"). No numeric FPS survived parsing.
  - sim+render, 1x640x480 (Open-X-like) and 3x320x180 (DROID-like): "about 2-4x better GPU memory efficiency and runs about 2x faster" (App. XI-C.1, Figs. 31-32); at 128 envs "ManiSkill3 uses just 3.5GB of GPU memory whereas Isaac Lab uses 14.1GB", Isaac Lab OOM beyond 128 envs (Sec. III-B, Fig. 2). Minimum memory with cameras: 1.7 GB vs 4.8 GB (App. XI-C).
  - square resolutions 512/256/128 (Figs. 33-35): "Isaac Lab runs at most about 1.25x faster when there are a high number of parallel environments with small camera resolutions"; at large resolutions ManiSkill3 "up to 2x in speed and 4x in GPU memory" (App. XI-C.2).
  - headline: "up to 30,000+ FPS in benchmarked environments" (Abstract); README: "RGBD + Segmentation data at 30,000+ FPS on a 4090 GPU"; ReplicaCAD "up towards 2000+ FPS with rendering" (App. VII-C); SIMPLER twins "60x to 100x the speed of the real world ... approximately 10x faster than the original" (Sec. III-B). The env count behind the 30,000 figure is not stated in text (Fig. 4 has no parsed values).
  - benchmark protocol: "FPS of taking 1000 random actions in the environment and fetching the 1000 visual observations"; reward/termination removed from timing (App. XI-A, XI-C).
- RL speed (Sec. IV-C, Fig. 11, RTX 4090, PickCube, 5 seeds, 95% CI): state-based PPO "near 100% success rate after about 1 minute of training, a 15x speed up relative to ManiSkill2"; RGB "solved after about 10 minutes ... 8x speed up". PPO uses "up to 4096 parallel environments ... for state based training and about 256 to 1024 environments for RGB" (App. IX-A).
- IL (Table II, state, 1000/100 demos, motion-planning data): DP PickCube 1.00/1.00, PushCube 0.96/0.95, StackCube 0.99/0.90, PegInsertionSide 0.66/0.38; ACT 1.00/0.70, 0.97/0.99, 0.97/0.50, 0.43/0.14; BC 0.03/0.00, 0.81/0.69, 0.00/0.00, 0.00/0.00. Table III (RGB): PegInsertionSide 0.00 for all; DP 1000-demo PickCube 1.00, PushCube 0.86, StackCube 0.81. Table IV PerAct (50 demos, 100 eval episodes): PushCube 0.96→1.00, StackCube 0.38→0.55 with aug.+multi-view.
- real2sim (Sec. III-E, Fig. 25): Octo and RT-1X on 4 GPU-parallelised SIMPLER tasks: correlation 0.9284, MMRV 0.0147.
- real robot? Yes, gripper only: Koch v1.1 arm, RGB PPO trained 15 M samples / 256 envs / ~1 h on 4090, "Evaluating the final checkpoint across 3 training runs in the real-world 8 times each yielded a 22/24 = 91.6% success rate" (Sec. IV-D); Fig. 13: 14 checkpoints x 3 seeds x 8 trials sim vs real. Vision-tactile key insertion cites 95.08% real success from the original work (Sec. III-E). No dexterous-hand real result.
- baselines beaten: Isaac Lab on memory and on rendering FPS at realistic resolutions (App. XI); ManiSkill2 on RL wall-clock (Fig. 11).

## Limitations stated by the authors (Sec. V)
- Room-scale scenes parallel-render "at a lower number of environments on one GPU".
- Sim2real "some reward engineering was required to encourage safer and more robust grasp behaviors"; static cameras only; green-screening needed.
- "Most GPU parallelized environments are rigidbody based. The soft body environments are not batched"; vision-tactile sim uses a different physics path.
- Benchmark caveats: only cartpole is "accurate" (App. XI); rasterisation vs Isaac ray tracing "not strictly apples-to-apples" (Sec. III-B); "may not extend to other environments" (App. XI-B).

## Quotable claims (verbatim, with section)
- "the fastest state-visual GPU parallelized robotics simulator with contact-rich physics targeting generalizable manipulation" (Abstract).
- "ManiSkill3 is so far the only simulation framework that completely supports heterogeneous GPU simulation." (Sec. III-C)
- "with 128 parallel environments for the benchmarked task, ManiSkill3 uses just 3.5GB of GPU memory whereas Isaac Lab uses 14.1GB." (Sec. III-B)
- "all visual RL baselines in ManiSkill3 typically do not use more than 256 to 1024 parallel environments as RL rollouts only run marginally faster with more environments beyond that point" (App. XI-C.2).
- "Dextrous Manipulation refers to tasks often involving multifingered hands and dense/rich contacts ... Not many special optimizations are made here." (App. VII-H)
- "Isaac Lab relies on the closed source Isaac Sim framework ... whereas ManiSkill3 relies on the open-source SAPIEN" (Sec. II).

- Throughput caveat for the survey table: the 30,000+ FPS figure is task-dependent and the curve values (Figs. 4, 30-35) did not parse; quote only the ratios and the 3.5 vs 14.1 GB point.
- Contrast with isaaclab_2025 note on rendering method (ray tracing vs rasterisation) and with simpler_2024 for the real2sim metrics (0.9284 / 0.0147 here vs SIMPLER's own).
- Two-hand relevance: multi-agent envs use a PettingZoo-style dict action space with a flattening wrapper (App. VII-F); humanoid manipulation tasks fix the legs "so that robot learning methods can focus on manipulation only" (App. VII-E). Neither source gives a two-dexterous-hand task.
