# orca_hand_2025 — ORCA: An Open-Source, Reliable, Cost-Effective, Anthropomorphic Robotic Hand for Uninterrupted Dexterous Task Learning (Christoph, Eberlein et al.; IROS 2025)

sources: papers/md/orca_hand_2025.md [f3967f2e] ; code/md/orca_hand_2025.md [4a99afd8, github.com/orcahand/orca_core]

## One-line contribution
A 17-DoF tendon-driven anthropomorphic hand with integrated binary tactile fingertips, "poppable" pin joints, and tendon-through-center-of-rotation self-calibration, assembled in under 8 hours for under 2,000 CHF and shown running over 10,000 continuous grasp cycles (~20 h) without hardware failure.

## Hand record
- maker / lab: Clemens C. Christoph, Maximilian Eberlein, Filippos Katsimalis, Arturo Roberti, Aristotelis Sympetheros, Michel R. Vogt, Davide Liconti, Chenyu Yang, Barnabas Gavin Cangan, Ronan J. Hinchet, Robert K. Katzschmann — Soft Robotics Lab, IRIS, D-MAVT, ETH Zurich (title page, affiliations).
- DoF / actuated DoF: "17DoF tendon-driven robotic hand" (Abstract). Breakdown (Sec. II-C/D, Table I): fingers 2-5 each have 3 actuated joints (PIP, MCP, ABD) = 12; thumb has 4 (IP, MCP, ABD, CMC) = 4; wrist has 1 (flexion/extension) = 1; total 12+4+1 = 17, all actuated (each non-wrist joint driven by its own antagonistic tendon pair, Sec. II-A). DIP joints on fingers 2-5 were intentionally removed/fixed ("The removal of the DIP joints on digits 2 to 5 was an intentional design decision," Sec. II-C) — not a passive/underactuated DoF, simply absent, freeing space for tactile electronics.
- actuation type: tendon-driven for all finger/thumb joints — "Each joint, except for the wrist joint, is actuated using two fishing lines (Nylon fibers braided into a 0.4 mm diameter rope) under tension" (one flexor, one extensor tendon per joint, Sec. II-A). The wrist instead uses a belt drive: "Instead of using tendon actuation for the wrist, we opted for a belt drive... a standard GT2 timing belt with fiberglass reinforcement" (Sec. II-D). Novel "poppable" pin joints: bearings sit in circular arc-shaped grooves that "dislocate instead of break" under excessive load (Sec. II-B).
- cost of BOM (quote verbatim): "built for a material cost below 2,000 CHF" (Abstract); "An open source, 3D-printable design with a cost of less than 2,000 CHF" (Sec. I, contributions).
- build time: "fully assembled in less than eight hours" (Abstract); "can be assembled by a single person without prior experience in less than eight hours" (Sec. I).
- weight: "The total weight of the hand is approximately 1.2 kg" (Sec. II, System Design intro).
- fingertip / grip force: payload test with a hand force sensor at constant 600 mA motor current, position control: "it can hold up to 10.5 kg (103 N) using all four fingers, and up to 2 kg (19.6 N) using only the index finger" (Sec. III-A).
- tactile sensing: yes, integrated. "we utilize force sensing resistors (FSR) (RP-C7.6-ST Thin-Film Pressure Sensor) mounted onto a solid FDM-printed PLA backplate, and covered by silicone-molded skin, to provide the hand with binary tactile feedback on all five fingertips" (Sec. II-E) — binary, not graded force, because the compliant/irregular silicone skin makes force magnitude ambiguous without contact-location info. Read via a voltage divider (10 kΩ) into an Arduino Nano Every analog input (Sec. II-E). Absolute detection threshold measured down to "as low as 0.05 N with perfect accuracy over 10 cycles" (Sec. III-E) despite the FSR's rated minimum trigger force of 0.29 N. Failure modes found: silicone-skin degradation raised one fingertip's threshold to 6.38 N, and copper sensor wires snapped near the MCP/ABD joints after ~4,500-7,000 grasp cycles on 3 fingertips (Sec. III-E, IV-C).
- control interface and rate: code README (quoted): "Orca Core is the core control package of the ORCA Hand. It's used to abstract hardware, provide scripts for calibration, tensioning and to control the hand with simple high-level control methods in joint space." Connection is serial (`/dev/ttyACM0` on Linux, `COMx` on Windows), motor families supported are Dynamixel and Feetech (`orca_core/hardware/dynamixel_client.py`, `feetech_client.py`, config auto-detects `motor_type`/`baudrate`, e.g. "1000000 # 1M for v2; 3M for v1"). A Python `orca_core/api/api.py` high-level API and CLI scripts (`calibrate.py`, `tension.py`, `neutral.py`, `manual_control.py`, `monitor_sensors.py`) are provided. No explicit control-loop rate (Hz) is stated anywhere in the parsed code or paper text; the accuracy/latency benchmark (Sec. III-B) reports "average latencies of less than 0.2 seconds" end-to-end for sine-tracking commands, not a control rate.
- licence: a `LICENSE` file exists in the repo (code/md file tree, top level) but its content/type was not captured by the parser — not stated which licence, and the paper text does not name one either (only "open-source" and "Design files, source code, and documentation are available at srl.ethz.ch/orcahand," Abstract).
- what the paper demonstrates: (1) 2.5 h continuous reliability test, 2,250 grasp cycles + wrist flex/extend every 16 s, "without breakage, motor shutdown, or excessive tendon slack," ended voluntarily not from failure (Sec. III-A); abstract claims durability up to "more than 10,000 continuous operation cycles—equivalent to approximately 20 hours—without hardware failure"; (2) accuracy/latency benchmark against the LEAP hand using AprilTag tracking at 0.2/0.5 Hz sine inputs on the index MCP/PIP — "similar accuracy to the LEAP hand," smoother motion, both hands "average latencies of less than 0.2 seconds" (Sec. III-B); (3) zero-shot sim-to-real RL: 4096 parallel ORCA-hand envs trained with an A2C IsaacGymEnvs wrapper (reused from the Faive rolling-contact hand codebase, ref [22]) for in-hand tennis-ball reorientation, deployed after "one hour of training with domain randomization," no tactile sensors used in RL "due to the additional complexity involved in accurately modeling them" (Sec. III-C); (4) imitation learning with a diffusion transformer policy for a repeated cube pick-and-place task on a Franka Emika Panda + ORCA hand, 214 demos over ~2h30m collected via ROKOKO motion-capture gloves, trained 500 epochs (~4h) on an RTX 4090; RGB/masked/mixed image ablation, masked-image policy best at 86.6% overall success across 6 subareas × 10 trials (Fig. 7); this policy deployed for "7h 17min (approx. 2,000 grasping cycles) with no human intervention on the ORCA hand's hardware" (Sec. IV-B); (5) teleoperated task showcase: stacking cubes, grabbing a plush toy and tennis ball, twisting open a Nutella jar, spinning a fidget spinner, writing "Hello" with a pen, picking up paper, pouring water between cups (Sec. IV-A); (6) tactile-sensor absolute-threshold characterization and degradation findings (Sec. III-E, IV-C).

## Setting
- hand(s): ORCA hand (17 DoF); compared against LEAP hand (accuracy/latency only, Sec. III-B) and named against Shadow Hand, InMoov, DexHand, Allegro Hand in the intro's cost/capability framing (Sec. I).
- simulator / physics: Isaac Gym via "the IsaacGymEnvs wrapper from [22]" (ref [22] = Toshimitsu et al., the Faive rolling-contact hand paper, faive_hand_2023 in this corpus) — 4096 parallel ORCA-hand model environments (Sec. III-C). No timestep, contact-model or GPU details stated in the parsed text.
- observation: for the diffusion-transformer IL policy — "three camera images along with proprioceptive data from both the robotic arm's end-effector and the hand" (two external cameras + one wrist-mounted camera, Franka Panda end-effector, Sec. III-D).
- action space: IL policy "output consists of an action chunk that predicts future actions" (Sec. III-D). RL: A2C policy over the 17 joints (tactile excluded from RL observations).
- objects / data: RL — a tennis ball for in-hand reorientation. IL — a 6 cm cube for pick-and-place (214 teleoperated demonstrations); teleoperated task set includes cubes, a plush toy, a tennis ball, a Nutella jar, a fidget spinner, a pen, paper, and cups of water (Sec. IV-A).

## Method
- paradigm: hardware design paper with three demonstrated learning paradigms: zero-shot sim-to-real RL (A2C in Isaac Gym), imitation learning (diffusion transformer policy from teleoperated demos), and pure teleoperation (no learning).
- reward or loss: not quoted for the RL task (Sec. III-C describes only the setup — A2C, domain randomization, 1 hour of training — with no reward formula given in the parsed text). IL: "a state-of-the-art robotic diffusion transformer [31]" is used but its loss is not restated in this paper (external architecture, cited not derived).
- key trick(s): tendon routing through/near each joint's center of rotation, decoupling joint positions so a per-joint linear motor-to-joint calibration suffices (Sec. II-A, II-F); auto-calibration Algorithm 1 — for each joint, move to flexion/extension mechanical stall limits to find motor limits, then compute the transmission ratio ρ_j = Δm_j / Δθ_j via linear interpolation against the CAD-derived ROM Δθ_j (Sec. II-F, quoted algorithm); poppable pin joints (Sec. II-B); ratchet spool re-tensioning without unscrewing (Sec. II-A).

## Evaluation
- metrics (exact definitions): accuracy/latency — AprilTag-derived ground-truth joint angle (σ=0.08° measurement error) vs. commanded sine-wave angle, recorded via a RealSense D435i at 60 fps in a ROS2 bag, latency and error computed offline (Sec. III-B). Reliability — grasp cycle count to failure/voluntary stop, motor current and temperature over time (Sec. III-A). Payload — max held weight at fixed 600 mA current until failure (Sec. III-A). Tactile absolute threshold (AT) — minimum indenter force (2 cm diameter, flat contact) registering an FSR reading above 0.01 V (Sec. III-E). IL success — ratio of successful cube pick-ups per subarea over 10 trials/subarea across a 6-subarea test grid (Fig. 7).
- headline numbers: 2,250 grasp cycles / 2.5 h reliability run with no failure; abstract's ">10,000 cycles, ~20 hours" durability claim; payload 10.5 kg (four fingers) / 2 kg (index only); tactile AT as low as 0.05 N; IL masked-image policy 86.6% overall success (Fig. 7) and a 7h17min/~2,000-cycle unattended deployment; both hands' teleop/control latency <0.2 s (Sec. III-B).
- baselines beaten: LEAP hand (accuracy/latency comparison only, "similar accuracy... while being far less bulky," "joints rotate more smoothly" than LEAP's, Sec. III-B) — not a head-to-head strength/cost/DoF benchmark table like leap_hand_2023's or ruka_2025's Table I/III; RGB-only vs. masked vs. mixed-image IL policy ablation (Fig. 7, masked wins).
- real robot? yes throughout; RL policy is sim-trained then deployed zero-shot to the physical hand (Sec. III-C, Fig. 6-B); no simulation-only headline numbers given.

## Limitations stated by the authors
- Tactile sensing durability (Sec. III-E / IV-C, quoted): "silicone skin... can drastically affect the AT of the sensors"; degradation occurred "in 2 fingertips after approx. 2,000 to 4,000 grasp cycles," and copper sensor wires snapped "in 3 fingertips after approx. 4,500 to 7,000 grasp cycles," concentrated near the MCP/ABD joints.
- AprilTag benchmark ceiling (Sec. III-B): "we cannot evaluate the accuracy and latency of the hands for faster movements, as the AprilTags can not be tracked at sine wave frequencies above 0.5 Hz or for step signals due to motion blur at 60 fps."
- Conclusion (Sec. V, quoted): "Prolonged use requires manual re-tensioning to maintain performance. To overcome this, we plan to develop an autonomous re-tensioning mechanism... Future work also includes integrating sensors directly into the learning pipeline."
- RL did not use tactile sensing "due to the additional complexity involved in accurately modeling them" (Sec. III-C) — an explicit sim2real gap the authors chose not to close.

## Notes for the survey
- The RL sim environment reuses "the IsaacGymEnvs wrapper from [22]," i.e. the Faive/rolling-contact-hand Isaac Gym codebase (see faive_hand_2023.md) rather than a bespoke ORCA simulator — cross-reference the two notes when discussing shared sim tooling across ETH SRL-lineage hands (ORCA's authors acknowledge access to a LEAP hand from Berkeley RLL, and cite the Faive/Toshimitsu Isaac Gym wrapper directly).
- Code confirms a URDF underlies the released kinematics even though no raw `.urdf` file is visible in the pruned file tree: `orca_core/kinematics/hand_kinematics.py` docstring reads "Forward kinematics for the ORCA hand from packaged URDF-derived constants," and a `tools/extract_urdf_kinematics.py` script exists. Treat this as "URDF-derived kinematics ship, packaged as constants, not as a standalone URDF confirmed in this parse" rather than a bare yes/no.
- Licence is unresolved (LICENSE file present, content not parsed) — same caveat as ruka_2025; do not assign a licence type in the survey's comparison table for ORCA.
- Cost/DoF/build-time triple for the survey's hand table: <2,000 CHF, 17 DoF (16 finger+thumb, 1 wrist), <8 h assembly, 1.2 kg, with binary integrated tactile — the only one of the six open-hardware hands in this batch with tactile sensing built into the base design (vs. RUKA/Ruka-v2's optional e-flesh add-on, LEAP's none, Faive/BiDexHand not stated).
