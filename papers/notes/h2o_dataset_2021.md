# h2o_dataset_2021 — H2O: Two Hands Manipulating Objects for First Person Interaction Recognition (Kwon et al., ICCV 2021)

sources: papers/md/h2o_dataset_2021.md [162d68ce] ; no code

## One-line contribution
571,645 egocentric RGB-D frames of 4 subjects bimanually manipulating 8 objects in 3 environments, with semi-automated MANO two-hand pose, 6D object pose, camera pose and verb-noun action-label annotation, released with baseline pose-estimation and interaction-recognition results (Abstract, Sec. 3-4).

## Setting
- capture setup: 5 Azure Kinect DK RGB-D cameras — 4 static + 1 head-mounted (egocentric), factory intrinsics, extrinsics from 9 IR-reflective spheres solved via PnP, head-camera jitter removed with Kalman filtering under a uniform-head-speed assumption (Sec. 3.1). Cameras hardware-synchronized ("less than 100 microseconds of lag between cameras") and offset by 160 μs to avoid IR interference ("a total maximum of only 0.74 ms of delay between cameras") (Sec. 3.4/4.1 text block). RGB and depth at 1280×720, 30 fps (Sec. 3.4 text block, labelled "4.1. Capture Setup" in the TOC but the body text with the resolution/fps appears at the end of Sec. 3.4).
- subjects: 4 participants (Sec. 4).
- objects: 8 objects, named only as the noun set used for action labels: book, espresso, lotion, spray, milk, cocoa, chips, cappuccino (Sec. 3.4).
- environments: 3 ("hall, office and kitchen") with "several different backgrounds" (Sec. 3.4 text).
- sequences / frames / hours: 571,645 RGB-D frames total (Abstract, Sec. 4); split subject-based (leave-one-subject-out) into 344,645 train / 73,380 validation / 153,620 test frames (Sec. 4.2). No sequence count is stated in the parsed text (only frame counts and per-action instance/frame-length statistics referenced to Fig. 4, which is not machine-readable here). At 30 fps, 571,645 frames ≈ 5.3 hours of capture (derived from the stated frame rate and count; not a number the paper itself states).
- action labels: 11 verb classes (grab, place, open, close, pour, take out, put in, apply, read, spray, squeeze) × 8 noun classes above, combined into 36 action classes after removing unrepresented pairs; one verb-noun label per frame, no overlapping labels, hand-annotated with the VIA tool (Sec. 3.4). "the least frequent action appearing 21 times" (Sec. 4.2). Hand-usage split: "both hands are used in 57.8%, only left hand in 12.4%, and only right hand in 29.8% of the dataset" (Sec. 4.2).

## Annotation types (hand model, joint two-hand+object annotation, verbatim metric definitions)
- hand model: MANO (Sec. 3.3) — "MANO factorizes human hand shape into a set of identity parameters β ∈ R^10 and a set of pose parameters θ ∈ R^51, storing angles for 15 skeleton joints plus global rotation and translation." Hand mesh function H_V(θ,β); skeleton function H_J(θ,β) returns N_J = 21 joints ("the 15 original ones plus 6 other for fingertips and wrist, to map to the OpenPose skeleton"). Both left and right MANO fits are provided per frame (Sec. 4). Shape β is fit once per subject on a single frame and then held fixed while θ is tracked per-frame for both hands (Sec. 3.3).
- object annotation: per-object 3D mesh reconstructed from hand-held Kinect scans via BADSLAM, textured in Blender by projecting scan-time RGB onto the mesh using BADSLAM camera poses; a Mask R-CNN mask predictor (trained on masks from projecting the 3D model) feeds DenseFusion for per-camera 6D pose, the highest-confidence camera's estimate is chosen, then refined by ICP against the merged 5-view point cloud (Sec. 3.2).
- joint two-hand + object fitting: multi-term energy per frame minimized to fit MANO to multi-view depth, using the already-estimated object pose (Sec. 3.3): "E = ... where N_c is the number of cameras. Here, L_s is a silhouette-based error term, L_2D and L_3D measure joint error in 2D and 3D, respectively, L_p and L_a are regularizers for pose, L_phy penalizes physically implausible interpenetrations between hand and objects, and L_m penalizes distance in 3D between the hand depth data and the MANO surface." Both hands are tracked (left and right) in the same optimization.
- contact/penetration metric definitions, verbatim: physical-constraint regularizer (App. S.1, "Physical constraint regularization"), "L_phy = L_a + λ_r · L_r, where θ_h are hand pose, θ_o are object pose parameters, L_a is attraction loss and L_r is repulsion loss. While repulsion loss penalizes interpenetration of hand and objects, attraction loss penalizes the cases in which hand vertices are in the vicinity of the objects but the surfaces are not in contact. In our experiments, we set λ_r to 0.8." (this is a fitting-time regularizer used to produce the annotations, not a released per-frame penetration metric on the dataset itself.)
- separately, a post-hoc **contact map**, verbatim: "for each vertex in the hand mesh, we find the nearest vertices on the object within a certain threshold (e.g. 2 cm). We then compute a histogram counting the number of neighbors for each vertex of the MANO mesh and normalize it to model contact hotspots on hand. We repeat the same procedure also for the object mesh to create a contact map on the object surface." (Sec. 6.1, "Contact Modelling"). No numeric interpenetration-depth or intersection-volume statistic is reported on the released data itself in the parsed text — the physical-constraint term is used only inside the annotation-fitting loss, and the contact map is a hotspot histogram, not a penetration measure.
- ablation of the loss terms (ground truth: 500 images, 5 views, fingertip annotations; App. Table S1, mean pixel/mm error not units-labelled explicitly beyond "Left/Right Mean(std)"): silhouette-only 2.87(±1.48)/3.02(±1.65) → +L_2D 1.25/1.31 → +L_3D 1.09/1.11 → +L_m 1.08/1.11 → +L_phy 0.95/1.05 → +L_phy+L_m 0.95/1.04 → + smoothing 0.82/0.93. Text: "L_phy improves both the physical plausibility and the accuracy of pose annotations."

## Method (dataset + baseline)
- paradigm: dataset paper with a joint two-hand + object pose estimation and interaction-recognition baseline (Sec. 5), built on a YOLOv2-backbone fully convolutional network extended from Tekin et al. [80] to predict 3D grids of per-cell pose vectors for left hand, right hand, and object simultaneously, each with its own confidence value (Sec. 5, "Pose Prediction").
- key trick(s): portable IR-reflective-sphere extrinsic calibration (avoids a fixed calibration rig); decoupled scan-then-track pipeline (BADSLAM mesh once, DenseFusion+ICP tracking per frame); subject-specific β fixed after one-frame fit, then per-frame θ-only tracking for speed/stability.

## Evaluation
- ground-truth verification (Table 2, Sec. 6.1): annotation error measured against manual 3D triangulation from 500 images × 5 views: object 1.10(±0.37) cm, left hand 0.82(±0.43) cm, right hand 0.93(±0.57) cm. "the error is approximately within a range of 1 cm."
- pose-estimation metrics (Sec. 6.2): "3D PCK metric for hand pose estimation, and the 2D reprojection and ADD metrics for object pose estimation as in [80]" (Fig. 7, curves not extracted as numbers here). Table 4 (left) reports pose error in mm for single-hand baselines evaluated per-hand on H2O: Hasson [33] left 3956 / object 6747 (trained for left), Hasson [33] right 4187 / object 6605 (trained for right), H+O [80] left 4142 / object 4806, H+O [80] right 3886 / object 5257, Ours (joint two-hand) left 4145 / right 3721 / object 4790 — the paper notes its method is "the first method and baseline for estimating the pose of two hands interacting with objects from a single RGB image," compared here against single-hand methods retrained separately per hand.
- action-recognition metrics/numbers (Sec. 6.2, Table 3, Table 4-right): modality ablation (Table 3a, accuracy %): LEFT HAND 33.61, OBJECT 48.55, RIGHT HAND 52.70, BOTH HANDS 58.92, ALL (hands+object) 79.25. Interconnection ablation (Table 3b): NO INTERCONNECTION 75.52, LEFT HAND-RIGHT HAND 76.76, HANDS-OBJECT 78.84, ALL INTERCONNECTIONS 79.25. Graph-term ablation (Table 3c, their TA-GCN): wo S_j 73.44, wo T_j,inter 75.52, wo T_j,intra 76.76, wo A_j,inter 76.35, wo A_j,intra 77.59, full TA-GCN 79.25. Comparison to prior action-recognition methods (Table 4-right, val/test accuracy %): C2D 76.10/70.66, I3D 85.15/75.21, SlowFast 86.00/77.69, H+O [80] 80.49/68.88, ST-GCN [95] 83.47/73.86, Ours (TA-GCN) 86.78/79.25 (best on both splits).
- baselines beaten: on pose estimation, their joint two-hand+object method is compared against Hasson et al. [33] and H+O [80] retrained separately per hand (numbers above; their right-hand and object errors are lower, e.g. 3721 vs 3886/4187 mm right hand, 4790 vs 4806-6747 mm object, though their left-hand error 4145 mm is not clearly lower than H+O's 4142 mm). On action recognition, their TA-GCN beats C2D, I3D, SlowFast, H+O and ST-GCN on both val and test accuracy (Table 4-right numbers above).
- comparison Table 1 lists FPHA, HOnnotate, ObMan, FreiHand, Panoptic, ContactPose by frame count and feature support, not by task accuracy — H2O is the only entry with real, multi-view, two-hand, egocentric, depth and action-labelled data simultaneously: "H2O|571k|✓|✓|✓|✓|✓|✓|✓|✓|✓" per Table 1, i.e. the only dataset checking every column.
- real robot?: none (human capture dataset).

## Limitations stated by the authors
Not framed as a dedicated "Limitations" section in the parsed text; self-acknowledged constraints are procedural: automated MANO tracking "may fail on some frames, due to challenges like (self-)occlusions, blur and cluttered background," requiring manual failure detection, removal, and temporal-smoothing replacement (Sec. 3). The dataset covers only 8 objects and 4 subjects in 3 environments (Sec. 4) — small relative to later egocentric corpora that cite it (see below).
