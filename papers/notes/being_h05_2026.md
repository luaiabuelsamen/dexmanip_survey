# being_h05_2026 — Being-H0.5: Scaling Human-Centric Robot Learning for Cross-Embodiment Generalization (Luo et al., arXiv 2026)

sources: papers/md/being_h05_2026.md [sha256 6253888b] ; code/md/being_h05_2026.md [commit e12ac44f]

## One-line contribution
A human-centric VLA (successor to Being-H0) that maps human MANO hand motion and 30 robot
embodiments into one "unified state-action space," trained with a Mixture-of-Transformers +
"Mixture of Flow" action expert, and deployed as a single generalist checkpoint on five real
robots, two of which carry a 6-DoF dexterous hand.

## Setting
- hand(s): real-robot dexterous hands used are "Inspire Hand" (on Franka FR3) and "LinkerBot O6"
  (on Unitree G1), both listed as "Dexterous (6DoF)" in Table 2 (sec. 7.1.1, p.23); also
  "Dexterous (6DoF)" hands on PND Adam-U (31 DoF, bimanual+head+waist) and BeingBeyond D1
  (14 DoF, single-arm). LeRobot SO-101 (6 DoF) uses a parallel "Gripper," not a dexterous hand.
  In pretraining data (Table 1, sec. 3.2, p.11), end-effector type is tagged "Grp" or "Dex" per
  embodiment; "Dex" rows include RMC RM65, BeingBeyond D1, PND AdamU, and partial Agibot-G1 /
  Leju kuavo 4 LB / Unitree G1edu-u3.
- simulator / physics: no physics engine used for the real-robot suite (real hardware); simulated
  benchmarks are LIBERO and RoboCasa (sec. 7.2, p.28-29), engine/timestep not stated in this
  paper.
- observation: RGB only, "224×224 resolution" for LIBERO/RoboCasa (sec. 7.2, p.28); multi-view
  RGB (wrist-mounted + third-person) for LIBERO (sec. 7.2.1, p.29); real-robot cameras per
  embodiment listed in Table 2 (ZED Mini, D435, 2×D435) (sec. 7.1.1, p.23).
- action space: "Unified State-Action Space" — fixed-length vectors partitioned into semantic
  slots (bimanual EEF pose, joint positions, gripper width, finger articulations, base
  velocity/heading); Cartesian actions as "relative delta displacements," rotations as
  "Axis-Angle notation," joint-space as "absolute radian values," explicitly without
  [-1,1] normalization (sec. 5.1.1, p.15-16).
- objects / data: UniHand-2.0 — "over 400 million samples extracted from 35,000 hours of
  multimodal data, totaling over 120B training tokens" (sec. 3, p.9): 16,000 hrs / 134M samples
  human egocentric video (25.6B tok), 14,000 hrs / ~1.5B frames robot data across 30 embodiments
  (45.7B tok, Table 1), 5,000 "equivalent hours" vision-text data (50.2B tok) (sec. 3.3, Fig. 4,
  p.9-11). Real-robot task data: "30 to 60 minutes of real-robot demonstration data" per task
  (sec. 7.1.1, p.24).

## Method
- paradigm: VLA (autoregressive text + continuous flow-matching action + discrete masked motion
  token prediction), human-centric pretraining then per-embodiment/cross-embodiment post-training.
- backbone VLM: "initialized from InternVL-3.5 [126]" (sec. 5.1, p.14). Parameter count not
  stated generally; the LIBERO/RoboCasa experiments explicitly state "a 2B backbone" (sec. 7.2,
  p.28, repeated p.29: "using only 224×224 RGB inputs and a 2B backbone"). No total-parameter or
  active-parameter number is given for the MoT+MoF action expert itself ("not stated"); the paper
  only asserts architecturally that MoF "decouples the total parameter count from the active
  parameter count" (sec. 5.1.2, p.16).
- action head — exact formulation (sec. 5.1, p.14 and sec. 5.2.3, p.18, eq. citations as rendered
  in the PDF-to-markdown conversion, which drops the numbered equations themselves but keeps the
  surrounding text verbatim):
  - "For action prediction, we adopt the Rectified Flow [33, 125] method, departing from discrete
    tokenization in favor of continuous actions." (sec. 5.1, p.14)
  - Continuous channel: "We model the continuous motion distribution using a time-conditioned
    velocity field vθ(x, t, c) ... For a target action a_i at temporal index i, we define a
    probability path via linear interpolation: x_t = (1 − t)x_0 + t·a_i for t ∈ [0,1]. The
    objective L_FM minimizes the mean squared error between the predicted velocity and the ideal
    vector field u_t(x_t) = a_i − x_0." (sec. 5.2.3, "Continuous Flow-Matching," p.18)
  - Discrete channel: "we leverage a pretrained tokenizer to quantize the motion into a discrete
    sequence z ∈ {1,...,|C|}^{Tz} ... The model is tasked to reconstruct the original codebook
    indices via a cross-entropy loss" — "Masked Motion Token Prediction" (sec. 5.2.3, p.18),
    tokenizer "derived via chunk quantization, as introduced in Being-H0 [10]" (p.18).
  - Hand-pose representation specifically: "We map parameters from the MANO hand model directly
    into this unified space. Specifically, the global wrist pose of the human hand is aligned
    with the robotic EEF subspace, while finger articulations are mapped to reserved
    'fine-manipulation' slots." (sec. 5.1.1, p.15). Human data itself is annotated via "HaWoR
    [98] to estimate hand poses via MANO parameters [99] and camera extrinsics" (sec. 3.1, p.10).
  - Deployment-time denoising: "Starting from Gaussian noise a^(0) ∼ N(0,I), we integrate the
    learned velocity field vθ using Euler steps ... In practice, we keep K < 10" denoising steps
    (sec. 6.1, p.22).
- action chunk length / control rate: LIBERO uses "action chunking with chunk size 8" (sec.
  7.2.1, p.29). Real-robot control rate is embodiment-specific and not tabulated per-robot, but
  stated in aggregate: "a single generalist Being-H0.5 checkpoint [achieves] real-time
  performance across diverse platforms (e.g., 10 Hz tabletop manipulators to 50 Hz humanoids)"
  (sec. 6.3, p.24).
- key trick(s): Mixture-of-Flow (shared "Foundation Expert" layers + routed "Top-K" specialized
  experts, sec. 5.1.2, p.16); Embodiment-Specific Adaptation, slot-wise adapter bank W_ESA
  updated only on active slot indices I_e (sec. 5.3.1, p.19-20); Manifold-Preserving Gating
  (discrepancy-guided gate on context features via Sliced-Wasserstein Distance, sec. 5.3.2,
  Fig. 7); Universal Async Chunking (per-embodiment committed-prefix / predicted-postfix
  splitting of each action chunk, sec. 5.3.3 / 6.2, p.21-24).

## Evaluation
- metrics: binary success/failure per real-robot trial under a "blind evaluation protocol" via a
  black-box inference server, "K=20" trials per policy per preset layout by default (sec. 7.1.1,
  p.25-26); LIBERO/RoboCasa use per-task mean success rate.
- headline numbers:
  - LIBERO (Table 4, p.28): Being-H0.5 specialist 98.9% average (L-Spatial 99.2, L-Object 99.6,
    L-Goal 99.4, L-Long 97.4); generalist 97.6% average. Best prior baseline in table: EO1 98.2%.
  - RoboCasa (Table 5, p.29): specialist 53.9% total avg (Pick&Place 36, Doors/Drawers 71.7,
    Others 57.6); generalist 53.3% (Pick&Place 40, Doors/Drawers 73, Others 52). Best RGB-only
    baseline quoted: π0.5 at 41.4% total.
  - Real robots (Fig. 10, category bar chart, sec. 7.1.2, p.26-27; values read off the chart, no
    exact numeric table given for per-category rates — flag as approximate): Being-H0.5-specialist
    "performs best on most categories"; Being-H0.5-generalist "only marginally behind"; both
    "significantly outperform π0.5, especially on long-horizon and bimanual tasks."
  - Ablation (Table 8, p.32) — AMBIGUOUS, flagging per HOWTO rule 3: flattened table reads
    "Hybrid (Ours) | Lab 0.33 | Wild 0.20" vs "w/o L_mask | Lab **0.35** | Wild **0.28**" (bold =
    higher for the ablated row), but the text claims "removing masked prediction leads to a clear
    drop in MWDS on both the lab-curated and in-the-wild splits" (p.32) — opposite of the printed
    numbers; not resolved here (extraction error or paper-internal contradiction).
  - Zero-shot: "a single Being-H0.5-generalist checkpoint can be deployed on Adam-U to solve
    previously unseen task–embodiment pairs" — described only qualitatively ("non-zero success
    rate"), no trial count or percentage given (sec. 7.1.2, p.27-28).
- baselines beaten: π0, π0.5, GR00T-N1, OpenVLA(-OFT), SpatialVLA, CoT-VLA, F1, InternVLA-M1,
  Discrete Diffusion VLA, X-VLA, EO1 (LIBERO, Table 4); 3DA, DP3, GWM, BC, GR00T-N1, π0.5, π0
  (RoboCasa, Table 5); π0.5 and Being-H0.5-scratch (real robots, Fig. 10).
- real robot? Yes — five platforms: PND Adam-U, Franka FR3 + Inspire Hand, Unitree G1 + LinkerBot
  O6, BeingBeyond D1, LeRobot SO-101 (Table 2/Fig. 8, p.23-25). Trial count: default K=20 per
  policy per layout (sec. 7.1.1, p.26); no aggregate total-trial number given.

dexterous-hand-evaluated: yes
"UerbodHmanoid|PND Adam-U|31|Bimanual+Head+Waist|Dexterous (6DoF)|ZED Mini|Movable (ego), dual-camera" and "Single arm + Dexterous hand|FR3 + Inspire Hand<br>BeingBeyond D1|13<br>14|Single-arm<br>Single-arm|Dexterous (6DoF)<br>Dexterous (6DoF)" (Table 2, sec. 7.1.1, p.23) — i.e. real-robot evaluation uses a Franka FR3 arm fitted with the "Inspire Hand," a Unitree G1 fitted with "LinkerBot O6," a PND Adam-U with an integrated dexterous hand, and a BeingBeyond D1 arm with a dexterous hand, all tagged "Dexterous (6DoF)" — distinct from the parallel-gripper LeRobot SO-101 also in the same real-robot suite.

## Limitations stated by the authors
No dedicated "Limitations" section in this paper. The closest self-critical statements: backbone
choice is acknowledged as consequential but unexplored — "the choice of the VLM backbone is
critical ... we intend to systematically benchmark alternative backbones in future exploration"
(sec. 5.1, p.14); Training-Time RTC is noted as inadequate for cross-embodiment use before their
own UAC fix — "RTC is typically instantiated for a single platform. This remains a significant
limitation for a cross-embodiment VLA" (sec. 6.2, p.23) (this is presented as a limitation of
prior work that motivates their own method, not a residual limitation of Being-H0.5 itself).
Zero-shot embodiment transfer is qualified: "the zero-shot success rate remains lower than
in-distribution performance and the motion precision is less reliable" (sec. 7.1.2, p.27-28).

## Quotable claims (verbatim, with section)
- "Being-H0.5 achieves state-of-the-art results on simulated benchmarks such as LIBERO (98.9%)
  and RoboCasa (53.9%), meanwhile performing strong cross-embodiment capabilities on five robotic
  platforms." (Abstract, p.1)
- "Despite advances in general data collection, data involving dexterous hands remains
  exceptionally rare, comprising less than 5% of existing corpora." (sec. 3, p.8)
- "Following the paradigm established by Being-H0, we treat human hand motion as a generalized
  manipulator template." (sec. 3.1, p.10)
- "Compared to its predecessor, UniHand-2.0 represents a 200× increase in scale." (sec. 1, p.4)

## Notes for the survey (which sections this feeds; contradictions with other notes)
Feeds the "yes" bucket for dexterous-hand-evaluated VLAs: four of five real-robot embodiments
(Inspire Hand, LinkerBot O6, plus unnamed-model "Dexterous (6DoF)" hands on Adam-U and D1) carry
a dexterous hand; only SO-101 is a parallel gripper. Code/repo mismatch: code/md (commit
e12ac44f) exposes only benchmark/inference/config scaffolding (`BeingH/benchmark/utils/policy.py`,
`BeingH/inference/beingh_policy.py`, dataset-transform configs) — no MoT/MoF model definition, no
rectified-flow action-expert source, and no config for any dexterous-hand embodiment; the only
posttrain configs present (`libero_robocasa.yaml`, `libero_all.yaml`, `robocasa_human.yaml`,
`so101_example.yaml`) are all gripper-only. The dexterous-hand claims cannot be cross-checked
against released code. Contact/penetration: not addressed as a modeled/measured quantity; the
paper mentions "collision avoidance" once in passing as an emergent property of shared
"Foundation Expert" motor primitives (sec. 5.1.2, p.16), not a reward or penalty term — this is a
VLA trained with cross-entropy + flow-matching MSE losses only, not RL. Reproducibility: paper
states intent to release "model weights, training pipeline, and simulation scripts... real-world
deployment infrastructure and a 1,000 GPU-hour pre-training recipe" (sec. 1, p.5); repo README
confirms Being-H0.5 weights are published, but the dexterous-hand deployment stack is absent from
what was parsed here.
