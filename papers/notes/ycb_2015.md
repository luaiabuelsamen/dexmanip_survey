# ycb_2015 — Benchmarking in Manipulation Research: The YCB Object and Model Set and Benchmarking Protocols (Calli et al., IEEE Robotics & Automation Magazine 2015)

sources: papers/md/ycb_2015.md [b82baf70] ; no code

## One-line contribution
A physical object set of 73 catalogue IDs in five categories (~$350, under 22 kg), scanned on the BigBIRD rig into 600 RGBD + 600 RGB images and Poisson watertight textured meshes with URDF/KinBody files, plus a five-part protocol template and five example protocols with baseline results (Abstract, Sec. III–V).

## Setting
- hand(s): n/a (object set). Demonstrations used HERB (Pitcher-Mug, Block Pick-and-Place), Yale Model T and Model T42 grippers (Gripper Assessment), PR2 (Peg Insertion, Box and Blocks) (Sec. V).
- simulator / physics: meshes integrated into MoveIt (collision objects), ROS URDF with mass properties, OpenRAVE KinBody; Gazebo URDF for the Table Setting scenario; signed-distance fields computable from the watertight meshes for CHOMP (Sec. III-C, V-3).
- observation: n/a.
- action space: n/a.
- objects / data (Table II, Sec. III-A): IDs 1–19 food (boxes, cans, wooden fruit), 20–33 kitchen, 34–53 tools, 54–68 shape items, 69–73 task items (box-and-blocks, 9-hole peg test, Lego, toy airplane, clear box + lid). Several IDs are sets (10 stacking cups, 100 wooden cubes, marbles in 4 sizes, washers in 7 sizes, nails in 3 sizes, clamps in 5 sizes). Mass and major dimensions per object, e.g. cracker box 453 g, 60×160×230 mm; sugar box 514 g, 38×89×175; mustard bottle 431 g, 50×85×175; tomato soup can 349 g, 66×101; banana 66 g, 36×190; power drill 895 g, 35×46×184; bowl 147 g, 159×53; plate 279 g, 258×24; Windex bottle 1022 g, 80×105×270; hammer 688 g; foam brick 28 g, 50×75×50; tennis ball 58 g, 64.7 mm. The md rendering of Table II is garbled for the mug, cups, washers and markers rows; those values are ambiguous and not quoted here. Object count "73" is the highest ID in Table II; the paper does not state a total.
- sensor setup for scans (Sec. III-B): BigBIRD rig, 5 RGBD sensors + 5 high-resolution RGB cameras in a quarter-circle arc; turntable rotated 3° at a time → 120 orientations → 600 RGBD + 600 RGB per object; fully automated, under 5 min per object. Poisson surface reconstruction → watertight meshes; segmentation masks by projecting meshes into each image; "Poisson reconstruction fails on certain objects with missing depth data; specifically, transparent or reflective regions".
- annotation types provided per object (Sec. III-B list): 600 RGBD images, 600 high-resolution RGB images, segmentation masks per image, calibration per image, texture-mapped 3D mesh. Physical properties: mass and dimensions (Table II). Not provided at publication: inertia, friction, simplified meshes (Sec. III-C, VI).

## Method
- paradigm: benchmark framework. Selection criteria: variety (shape, size, transparency, deformability, texture, grasp difficulty), use (assembly, tools, rehabilitation tests), durability, cost, portability (Sec. III-A).
- protocol template (Sec. IV-A): (1) task description, (2) setup description (objects, initial poses, clutter), (3) robot/hardware/subject description (initial state, a priori information such as whether shape models are given), (4) procedure, (5) execution constraints. Benchmark = adopted protocol + scoring + "to submit" (Sec. IV-B).
- scoring guidance, verbatim: "it is usually a good practice to avoid binary (success/fail) measures; if possible, the scoring should include the intermediate steps of the task, giving partial points for a reasonable partial execution" (Sec. IV-B2). Users should submit "the reasons of the failed attempts".
- example protocols (Sec. V): Pitcher-Mug (10 specified initial configurations; score penalises liquid left in pitcher or spilled); Gripper Assessment (shape + tool objects, scoring table); Table Setting (mug, fork, knife, spoon, bowl, plate; scored by final pose accuracy; Gazebo URDF provided); Block Pick and Place (points for completion and precision); Peg Insertion Learning Assessment (board perturbed a fixed distance in a random direction); Box and Blocks (blocks moved over a barrier in fixed time).

## Evaluation
- metrics: per-protocol scores as above; no statistical treatment of trial counts anywhere in the paper.
- headline numbers: Pitcher-Mug on HERB 8/10 configurations, failures were pouring-path planning after a successful grasp (Sec. V-1). Peg insertion, PR2 with a learned linear-Gaussian controller: 4/10 at 5 mm perturbation after 1 s, no improvement with longer execution; 0/10 at 10 mm (Sec. V-5). Block Pick and Place on HERB: placement imprecise because the open-loop push grasp leaves block-in-gripper pose unknown (Sec. V-4). Box and Blocks on PR2: 10 runs × 2 min with a random-pick heuristic; counts in App. C.5 (not in the read range). Gripper Assessment: Model T fails on small and flat objects, Model T42 succeeds on flat objects via nail-like tips but cannot interlace fingers (Sec. V-2).
- baselines beaten: none claimed; these are baselines for others to beat.
- real robot? yes, HERB, PR2, two Yale grippers; trial counts 10 per protocol where stated.

## Limitations stated by the authors
- Poisson reconstruction fails for transparent/reflective objects; better models promised (Sec. III-B). No simplified meshes (Sec. III-C). Inertia and friction "plan to undertake" (Sec. VI). Protocols are expected to be revised by the community; appendices to be moved to arXiv (Sec. V, VI).

## Quotable claims (verbatim, with section)
- "Access to the objects is crucial to performance benchmarking as many aspects of the manipulation process cannot be modeled, thereby requiring experiments to demonstrate success or examine failure modes." (Sec. I)
- "Current cost for the objects is approximately $350." / "fits in a large-sized suitcase and be below the normal airline weight limit (22kg)" (Sec. III-A)
- "variations caused by incomplete descriptions of test setups and execution processes induce discrepancy in measurements and won't speak to some quantifiable performance" (Sec. IV-A)

## Notes for the survey
- Feeds the object-set section. dexycb_2021 uses 20 of these objects (via YCB-Video); GRAB uses ContactDB objects, not YCB. Any YCB mass we quote should come from Table II, with the garbled rows excluded.
- The 2015 "avoid binary scoring" advice is the ancestor of LBM's milestone task-completion and beyond_binary's progress metrics; the paper itself gives no statistics.
- Scan data are static object appearance and geometry only: no grasps, no contact, no dynamics.
