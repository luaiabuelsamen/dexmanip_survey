# groot_n1_2025 — GR00T N1: An Open Foundation Model for Generalist Humanoid Robots (NVIDIA, arXiv 2025, arXiv:2503.14734)

sources: papers/md/groot_n1_2025.md [sha256 76e38cf6] ; code/md/groot_n1_2025.md [commit 51d4c89f]

## One-line contribution
GR00T N1 is a dual-system VLA for humanoids: a frozen-language, otherwise-finetuned Eagle-2 VLM (System 2, 1.34B of 2.2B total params) feeds a DiT flow-matching action head (System 1, action chunk H=16, closed-loop at 120Hz) trained on a "data pyramid" mixing real teleop, DexMimicGen simulation, neural-generated video, and human egocentric video (592.9M frames / 8,375.7 hours total, Table 7); deployed on the Fourier GR-1 humanoid with Fourier dexterous hands for bimanual language-conditioned manipulation (Abstract).

## Setting
- hand(s): **Fourier dexterous hands** on the Fourier GR-1 humanoid — named explicitly ("GR-1 humanoid robot equipped with Fourier dexterous hands," Sec. 4.1) for both the real robot and the GR-1 Tabletop sim benchmark. **DoF/finger count: not stated anywhere in the parsed paper or code text** — do not infer. The DexMimicGen suite's second embodiment is "Bimanual Panda Arms with Dexterous Hands" (Sec. 4.1) with no hand model named at all.
- arm: Fourier GR-1 humanoid (bimanual arms + waist + neck actuated); teleoperated via VIVE Ultimate Tracker (wrist) + Xsens Metagloves (fingers), or alternatively Apple Vision Pro / Leap Motion, retargeted via inverse kinematics (Sec. 3.1, Fig. 6). DexMimicGen data generation uses a whole-body IK controller "based on mink" (Sec. 3.2).
- bimanual: yes — real-world tasks explicitly require left-to-right handover and multi-agent coordination (Sec. 4.4, Fig. 11).
- simulator / physics: RoboCasa simulation framework (Nasiriany et al., 2024) for the Kitchen and GR-1 Tabletop benchmarks; DexMimicGen (Jiang et al., 2024) for the cross-embodiment suite and for generating pretraining sim trajectories. Underlying physics engine, timestep, and contact-solver settings are **not stated** in the parsed paper text.
- observation: RoboCasa Kitchen — 3 RGB cameras (left, right, wrist) + end-effector/base pose + gripper state; GR-1 Tabletop / real robot — single egocentric RGB from a head-mounted camera + robot state (Sec. 4.1).
- action space: RoboCasa — relative end-effector position/rotation + gripper state; DexMG/GR-1 — joint position and rotation of both arms and hands, plus waist and neck, with an optional end-effector-based alternative (Sec. 4.1). Action chunk length **H=16** timesteps (Sec. 2.1); System 1 runs closed-loop at **120Hz**; teleoperation/data capture at **20Hz** (Sec. 3.1); the VLM (System 2) runs at **10Hz** on an NVIDIA L40 GPU (Sec. 1).
- objects / data: see pretraining mixture and evaluation tables below.

## Method
- paradigm: Vision-Language-Action (VLA), dual-system architecture — VLM (System 2, "reasoning") + diffusion-transformer flow-matching policy (System 1, "acting"), jointly trained end-to-end (Sec. 1-2).
- **Backbone (System 2):** NVIDIA Eagle-2 VLM (Li et al., 2025), finetuned from a SmolLM2 LLM + SigLIP-2 image encoder. "our publicly released GR00T-N1-2B model has 2.2B parameters in total, with 1.34B in the VLM" (Sec. 2.1). Images at 224×224, pixel-shuffled to 64 tokens/frame. Uses **middle-layer** (12th layer for the 2B model), not final-layer, LLM embeddings — "resulted in both faster inference speed and higher downstream policy success rate" (Sec. 2.1). Language component of the VLM is kept **frozen** during pre- and post-training (Sec. 2.3).
- **Action head (System 1):** a DiT variant (Peebles and Xie, 2023) denoted V_θ, alternating cross-attention (to VLM tokens φ_t) and self-attention (over noised action tokens A^τ_t and state q_t) blocks, "similar to Flamingo... and VIMA" (Sec. 2.1), followed by an embodiment-specific Action Decoder MLP.
- **loss (quoted, Sec. 2.1):** "Given a ground-truth action chunk A_t, a flow-matching timestep τ ∈ [0,1] and sampled noise ε ∼ N(0,I), the noised action chunk A^τ_t is computed as A^τ_t = τA_t + (1−τ)ε. The model prediction V_θ(φ_t, A^τ_t, q_t) aims to approximate the denoising vector field ε − A_t by minimizing the following loss:" — **the equation itself (Eq. 1) is embedded as an unextracted math image in the PDF→markdown conversion and is not present as parseable text**; do not reconstruct it from memory. "As in Black et al. (2024), we use p(τ) = Beta(s−τ/s; 1.5, 1), s=0.999." Inference uses K-step forward-Euler denoising from A^0_t ∼ N(0,I); "we found K=4 inference steps to work well across all embodiments." Auxiliary loss (App. F, quoted verbatim): "L_det = ‖x_pred − x_gt‖². Thus, the final loss is given by: L = L_fm + L_det."
- key trick(s): **latent actions** — a VQ-VAE trained on consecutive video frames to label action-less human/neural video with a shared cross-embodiment latent-action codebook, treated as a distinct "LAPA" embodiment and trained with the same flow-matching loss (Sec. 2.2); **neural trajectories** — fine-tuned image-to-video models 10× the 88 real teleop hours into 827 generated hours with novel language prompts (Sec. 2.2, 3.2); **DexMimicGen simulation trajectories** — object-centric demonstration transformation/replay, generating 780,000 sim trajectories (pre+post-training combined) "equivalent to 6,500 hours... of human demonstration data — in just 11 hours" (Sec. 2.2).

## Pretraining data mixture (Table 7, and Sec. 3)
- **Real-robot:** GR00T N1 Humanoid Pre-Training (GR-1 teleop) 6.4M frames / 88.4 hr @ 20fps, egocentric; Open X-Embodiment subsets — DROID 23.1M/428.3hr, RT-1 3.7M/338.4hr, Language Table 7.0M/195.7hr, Bridge-v2 2.0M/111.1hr, MUTEX 362K/5.0hr, Plex 77K/1.1hr, RoboSet 1.4M/78.9hr; AgiBot-Alpha 213.8M/1,979.4hr ("140,000 trajectories available at the time of launching our training run," Sec. 3.1); RH20T-Robot 4.5M/62.5hr. **Total robot data: 262.3M frames / 3,288.8 hr.**
- **Human video (no ground-truth actions, latent-action labels only):** Ego4D 154.4M/2,144.7hr, Ego-Exo4D 8.9M/123.0hr, Assembly-101 1.4M/19.3hr, HOI4D 892K/12.4hr, HoloAssist 12.2M/169.6hr, RH20T-Human 1.2M/16.3hr, EPIC-KITCHENS 2.3M/31.7hr. **Total human data: 181.3M frames / 2,517.0 hr.**
- **Simulation (synthetic, DexMimicGen/RoboCasa):** GR-1 Simulation Pre-Training 125.5M frames / 1,742.6 hr — 540,000 demonstrations, 10,000 per (source, target) receptacle pair across 54 unique receptacle-category combinations (Sec. 3.2). **Total simulation data: 125.5M / 1,742.6 hr.**
- **Neural-generated:** GR-1 Neural Videos 23.8M frames / 827.3 hr @ 8fps (Sec. 3.2; generation cost "~105k L40 GPU hours (~1.5 days) on 3,600 L40 GPUs"). **Total neural data: 23.8M / 827.3 hr.**
- **Grand total (Table 7): 592.9M frames / 8,375.7 hr.**

## Embodiments in the mixture and evaluation
- **Pretraining embodiments:** Fourier GR-1 humanoid (real + sim + neural), OXE arms (Franka-Panda-class DROID, WidowX Bridge-v2, RT-1's mobile manipulator, xArm-class Language Table, and MUTEX/Plex/RoboSet arms), AgiBot's 100-robot fleet, plus a synthetic "LAPA" latent-action embodiment spanning both robot and human video.
- **Evaluation embodiments (Sec. 4.1):** (1) RoboCasa Kitchen — **Franka Emika Panda arm with a parallel-jaw gripper** (not dexterous); (2) DexMimicGen Cross-Embodiment Suite — three bimanual embodiments: Panda arms + parallel-jaw grippers, Panda arms + unnamed "Dexterous Hands," and **GR-1 humanoid + Dexterous Hands**; (3) GR-1 Tabletop Tasks — **GR-1 humanoid equipped with Fourier dexterous hands**. Real-world evaluation (Sec. 4.2): Fourier GR-1 humanoid with Fourier dexterous hands only.

## Evaluation
- exact success criterion: for simulated benchmarks, task-defined binary or staged success per the cited benchmark's own protocol (RoboCasa/DexMimicGen); no metric threshold in metres/radians is given in the parsed text. Real-world uses "a partial scoring system to capture model behavior across different execution phases" (Sec. 4.3) — partial credit is stated qualitatively (e.g. "0.5 stands for grasping the object correctly but failing to place the object into the container," Sec. 4.4) but no full rubric is quoted.
- episodes/trials: sim — "average success rate over 100 trials, taking the maximum score of the last 5 checkpoints" written every 500 steps (Sec. 4.3). Real — 10 trials/task, except Machinery Packing (5 trials, 30s time limit, scored as fraction of 5 objects placed) and the two pre-training generalization probes (5 objects × 3 trials = 15 trials each, Sec. 4.4).
- baselines: BC-Transformer (RoboMimic GMM Transformer policy) and Diffusion Policy (Chi et al., 2024, U-Net); both **re-run** by the authors on identical post-training data budgets (Sec. 4.3), not quoted from their original papers.
- **Table 2 (sim, 100 demos/task, headline):** RoboCasa / DexMG / GR-1 / Average — BC-Transformer 26.3% / 53.9% / 16.1% / 26.4%; Diffusion Policy 25.6% / 56.1% / 32.7% / 33.4%; **GR00T-N1-2B 32.1% / 66.5% / 50.0% / 45.0%**.
- **Ambiguity flagged:** Table 4's per-task breakdown at 100 demos (9 DexMG tasks) arithmetically averages to **DP=46.9%, GR00T=58.5%** for DexMG (verified by summing the 9 per-task cells and dividing by 9), not the 56.1%/66.5% reported in Table 2's DexMG column — the RoboCasa and GR-1 columns of Table 2 do match Table 4's arithmetic averages exactly (25.6/32.1 and 32.7/50.0). ## Fine-tuning recipe
- **Paper (Sec. 2.3, Post-training):** fine-tune the pretrained model per single embodiment; "we keep the language component of the VL backbone frozen and fine-tune the rest of the model." Table 6 hyperparameters: batch size 128 (small-task-count DexMG) or 1024 (default); gradient steps 20,000–60,000 (vs. 200,000 for pretraining); same optimizer/LR/schedule as pretraining (AdamW, lr 1e-4, cosine schedule, 0.05 warmup). Compute-constrained single-A6000 fine-tuning: batch size up to 200 tuning only adapters (state/action encoders+decoder) + DiT, or up to 16 if also tuning the vision encoder (Sec. 2.3). Post-training with neural trajectories co-trains real + generated data at a 1:1 sampling ratio, using IDM-labeled (for real robot) or latent/IDM-labeled (for sim) pseudo-actions (Sec. 2.3).
- **Code (current Isaac-GR00T repo, commit 51d4c89f, N1.7 generation — this is a later model generation than the paper's GR00T-N1-2B, see mismatch note below):** `gr00t/experiment/launch_finetune.py --base-model-path <ckpt> --dataset-path <data> --embodiment-tag NEW_EMBODIMENT --modality-config-path <cfg> --num-gpus <n> --max-steps 2000 --global-batch-size 32`. `--state_dropout_prob` (model-config default 0.8; finetune-CLI default 0.2; benchmark scripts override per-suite: LIBERO 0.2, SimplerEnv Bridge 0.8, SimplerEnv Fractal 0.5).

## Contact / penetration handling
**Not addressed.** No mention of interpenetration, contact force, or a contact-solver setting anywhere in the parsed paper or code text; task success is judged behaviorally (object placed/grasped) via the partial-scoring rubric above, not via a measured or penalized contact/penetration metric.

## Paper/code mismatches (code/md is the current Isaac-GR00T repo, commit 51d4c89f — a later N1.7 release, not the exact GR00T-N1-2B checkpoint the paper describes)
- **VLM backbone changed:** paper describes Eagle-2 (SmolLM2 + SigLIP-2, 1.34B/2.2B total). Current repo README: "VLM backbone changed from vendored Eagle, `nvidia/Eagle-Block2A-2B-v2`, to `nvidia/Cosmos-Reason2-2B` via Qwen3-VL" for N1.7; `gr00t/configs/model/gr00t_n1d7.py`'s `Gr00tN1d7Config` docstring states "Gr00tN1d7 uses the Cosmos-Reason2-2B (Qwen3-VL architecture) VLM backbone, replacing the Eagle backbone used in Gr00tN1d6." Neither backbone in the current repo is the paper's Eagle-2.
- **Action horizon changed:** paper H=16 (Sec. 2.1) matches the repo's own stated N1.6 value; the repo changelog states "action_horizon expanded from 16 to 40" for N1.7 — so the commit actually parsed here (N1.7) no longer matches the paper's H=16.
- **State/action dimensions and diffusion-layer count:** repo changelog: "State and action dimensions expanded from 29 to 132" and "Action head remains flow-matching DiT, but changes from 32 to 16 diffusion layers" for N1.7 vs. N1.6. The paper gives neither a state/action dimension count nor a DiT layer count, so these repo numbers cannot be checked against the paper directly — they describe the repo's own version history, not a paper claim.
- **Action-head source code not recoverable from code/md:** the actual `gr00t/model/gr00t_n1d7/` and `gr00t/model/modules/` implementation files (e.g. the DiT/`dit.py`, `alternate_vl_dit.py`, and the `Gr00tN1d7ActionHead` class body) are **not included** in code/md's "Python signatures" extraction — only test file signatures/docstrings that exercise them (`tests/gr00t/model/test_action_head.py`: "Test Gr00tN1d7ActionHead: flow matching forward, get_action, feature encoding"; `tests/gr00t/policy/test_gr00t_policy_gpu.py` docstring naming `gr00t_n1d7.py`, `qwen3_backbone.py`, `dit.py`, `alternate_vl_dit.py` as the modules exercised by `model.get_action() (backbone forward + DiT diffusion denoising)`). The literal loss/forward-pass code cannot be quoted from what was parsed; do not reconstruct it from memory.
- **Embodiment scope widened:** the paper's real-robot embodiment is Fourier GR-1 only. The current repo's README front page and checkpoints/embodiment tags cover Unitree G1, AgiBot G1, and a "YAM" arm, plus a `UNITREE_G1_SONIC` whole-body-control tag (GEAR-SONIC) not described in the paper at all.

## Limitations stated by the authors (Sec. 4.6)
"Currently, our GR00T N1 model focuses primarily on short-horizon tabletop manipulation tasks." Future work: long-horizon loco-manipulation (needs better hardware/architecture/data); a stronger VLM backbone for spatial reasoning; synthetic data generation "still face challenges in generating diverse and counterfactual data, while adhering to the laws of physics, limiting the quality and variability of synthetic datasets."

## Reproducibility
Code (Isaac-GR00T, Apache-2.0 per current README), the GR00T-N1-2B checkpoint, training data, and simulation benchmarks are stated as publicly released ("Our GR00T-N1-2B model checkpoint, training data, and simulation benchmarks are publicly available here: GitHub and HuggingFace Datasets," Sec. 1). From code/md as parsed: the LIBERO, SimplerEnv (Fractal/Bridge), and SO100 benchmarks each have a self-contained finetune+eval README (current repo table, "Reproducing Benchmark Results"); the paper's own RoboCasa/DexMG/GR-1 tables are not directly reproducible from what code/md captured, since the model source (action head, VLM integration) bodies were not included in the extraction and the current repo has moved to a different model generation (N1.7) than the one evaluated in the paper.
