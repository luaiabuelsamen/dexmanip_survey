# dex1b_2025 — Dex1B: Learning with 1B Demonstrations for Dexterous Manipulation (Ye, Wang, Yuan, Yang, Li, Zhu, Qin, Zou, Wang; RSS 2025)

sources: papers/md/dex1b_2025.md [sha 5ca58880] ; no code

## One-line contribution
An iterative optimization-then-generative-model data engine (5M optimization seed -> CVAE proposal -> simulator filter/debias -> retrain, repeated) produces Dex1B, 950M (~1B) purely synthetic grasping and articulation demonstrations across three robot hands and 6,000+ objects, and the accompanying DexSimple CVAE baseline beats prior grasp-synthesis SOTA by 22 points and transfers directly sim-to-real.

## Setting
- hand(s): three robot hands used for the 1B-demo benchmark — Shadow Hand (22 DoF), Inspire Hand (6 DoF param), Ability Hand (6 DoF param)
  - grasp-synthesis evaluation benchmark (Table II) uses Shadow Hand only (in Isaac Gym, following the DexGraspNet protocol)
  - real-robot demos use xArm+Ability Hand and H1 (humanoid) + Inspire Hand. arm: xArm and a Unitree/other H1 humanoid base (arm details for H1 not stated beyond "H1"). single/bimanual: single-hand.
- simulator / physics: benchmark evaluation and dataset filtering run in ManiSkill/SAPIEN [44,50]
  - the DexGraspNet-benchmark grasp-quality comparison (Table II) is run in Isaac Gym
  - optimization pipeline itself uses WarpLang with a BVH mesh structure for SDF queries (not a physics engine, a differentiable-geometry optimizer).
- observation: for DexSimple, a point cloud P ∈ R^{N×3} (full object-mesh point cloud during data generation, single-view depth-camera point cloud at policy deployment/real-robot time) encoded by PointNet into a global feature f_obj ∈ R^d (d=256) and per-point local features f_p
  - for real-robot deployment a third-person camera (xArm) or egocentric camera (H1), hand-eye calibrated.
- action space: a hand pose g = (T, R, θ), T ∈ R^3 global translation, R ∈ SO(3) global rotation, θ ∈ R^d joint angles (d=22 Shadow Hand, d=6 Inspire/Ability Hand)
  - DexSimple's CVAE outputs key hand poses at "critical interaction points," with the remaining reach/lift/open trajectory filled in by a separate motion-planning optimization (not learned)
  - the BC-w.-PointNet baseline instead predicts chunked actions for n=50 frames, merged via ACT-style temporal weighting.
- objects / data: benchmark spans >6,000 objects
  - grasping task uses all 5,751 DexGraspNet object assets (minus objects that can't stand stably on a table — DexGraspNet's own poses have ~90% table collisions since it targets free-space grasping, not tabletop)
  - articulation task uses 650+ DexArt/ManiSkill articulation assets. Seed dataset: 5M optimized poses -> 50M CVAE proposal dataset -> 500M -> final 950M (~1B) successful trajectories, built by repeating [train DexSimple on current dataset -> generate 10x proposal -> filter/rebalance in sim] (Sec. V-B "Dataset Curation"). Comparison human-demo baselines: DexYCB (20 objects, ~500 trajectories/hand) and ARCTIC (10 articulation objects, 301 trajectories total) — Dex1B claims 700x more demonstrations than DexGraspNet (1.32M) at similar object-set scale (Sec. I, Table I).

## Method
- paradigm: hybrid optimization + generative model (CVAE) data-generation pipeline, i.e. this is a dataset/data-engine paper, not primarily a policy paper, though it also proposes and evaluates the DexSimple CVAE model and a BC baseline as consumers of the data.
- algorithm: seed dataset built by gradient-based pose optimization (spheres-approximate hand geometry, ~10 spheres/link) minimizing E_grasp = E_fc + w_dis*E_dis + w_sdf*E_sdf + w_j*E_j + w_s*E_s for grasping (E_fc = force closure term) or E_arti = E_tws + w_dis*E_dis + w_sdf*E_sdf + w_j*E_j + w_s*E_s for articulation (E_tws = task-wrench-space term approximating target vs. current wrench space; torque-aligned wrench for revolute joints, force sampled from a 30° cone for prismatic joints). DexSimple is a conditional VAE: PointNet point-cloud encoder -> MLP encoder produces latent mean/std -> MLP decoder reconstructs hand pose g
  - conditioned on object point-cloud feature and, for diversity-oriented generation, on a local feature f_p at a single object point associated with each hand pose (found via the heading vector from palm center to the thumb-tip/middle-tip midpoint). CVAE loss: L = λ_R*L_R + λ_KL*L_KL + λ_SDF*L_SDF, with L_R = ||g − ĝ||² (reconstruction), L_KL = D_KL(N(μ,σ²) || N(0,I)), and L_SDF a point-sphere signed-distance penetration loss (hand as spheres, object as a sampled point cloud) used because full BVH mesh-sphere SDF at every training step is too slow (Sec. IV, "Objectives").
- key trick(s): post-optimization step E_post = w_dis*E_dis + w_sdf*E_sdf + w_j*E_j + w_s*E_s (no task term) applied to CVAE samples — 100 post-optimization iterations vs. 6,000 for pure optimization, ~100x faster sampling
  - debiasing by conditioning generation on under-represented object-point/heading-direction "association points" and sampling inversely proportional to their existing frequency, plus sampling more for objects with fewer existing successful demos
  - iterative retrain-on-expanded-dataset loop (repeated across the 5M -> 50M -> 500M -> 950M stages).
- Reproducibility of the pure-optimization step is reported explicit vs DexGraspNet: 30x faster (2 min for 2,000 grasps over 6,000 steps on one RTX-3090) and higher raw success rate (27% vs 20% for ShadowHand)
  - with the trained network initializing poses, 700x faster than pure optimization.

## Evaluation
- metrics: on the DexGraspNet grasp-synthesis benchmark (Table II) — quality: Success Rate (SR), Q1-score, Penetration (Pen, lower better)
  - diversity: entropy mean (H mean, higher better) and entropy std (H std, lower better). On the Dex1B lifting/articulation benchmarks (Table III) — success rate defined as: lifting = lift object to 0.4 m height while maintaining hand-object contact
  - articulation = increase joint angle of an articulated object by 0.5 rad while maintaining contact (Sec. V-B "Tasks Definition"). Real-robot: per-object trial success fraction over 5 trials/object.
- headline numbers: DexSimple (with post-optimization, no filter) achieves SR 86.0%, Q1 0.125, Pen 0.13, H mean 8.56, H std 0.15 on DexGraspNet — best among DDG (67.5% SR no-opt), UGG (64.1% SR w/opt), UDG, GraspTTA (Table II)
  - with an added learned filter (UGG-style discriminator) DexSimple reaches SR 92.6% vs UGG's 72.7%. Paper's abstract-level claim: "22% performance improvement over previous best methods on grasp synthesis tasks" (Sec. I) — this reads as the SR gap between DexSimple w/opt (86.0) and UGG w/opt (64.1), i.e. +21.9 points, so the "22%" is a percentage-point gap, not a relative percentage
  - flagged as ambiguous per HOWTO rule 4. Lifting/articulation transfer (Table III): DexSimple trained on Dex1B scores 47.17/53.02 (train/test on DexYCB-style eval) vs. 43.49/21.21 when trained on DexYCB itself — i.e., training on the 1B synthetic set generalizes far better to held-out objects than training on the smaller human-annotated set (a ~32-point test-set gap, 21.21→53.02). Articulation (ARCTIC-style eval): DexSimple on Dex1B reaches 72.00/73.49 (train/test) vs. 48.75/23.08 trained on ARCTIC directly.
- scaling result: Fig. 8, downsampling the training set for both lifting and articulation tasks — success rate "consistently improves with more training data" for DexSimple on both tasks
  - lifting degrades faster than articulation as data shrinks (paper attributes this to lifting needing precise per-object geometric understanding vs. articulation's more transferable trajectory-execution skill). No single number is given in the parsed text for the exact curve values — only the qualitative shape and the differential degradation claim are stated (figure not tabulated in the parsed markdown).
- ablation (Table IV, on DexGraspNet benchmark): removing L_sdf collapses success rate from 63.7% to 0.7% (Pen rises 0.29→0.92) — geometric/penetration loss is "indispensable"
  - removing L_D (distance/contact loss) drops SR to 42.0% (Q1 0.075→0.044) while penetration actually improves slightly (0.29→0.23), showing L_D trades a bit of penetration for contact stability and success rate.
- baselines beaten: DDG, GraspTTA, UniDexGrasp (UDG), UGG on DexGraspNet
  - vanilla "BC w. PointNet" and models trained on DexYCB/ARCTIC on the lifting/articulation benchmarks
  - DexDiffuser (retrained on Dex1B/xArm+Ability platform, since it targets Allegro Hand originally) in real-world trials.
- real robot? Yes — xArm+Ability Hand and H1 (humanoid)+Inspire Hand, direct sim-to-real pose deployment (open-loop key-frame + motion planning + 128-pose IK sampling, no closed-loop policy). Trial counts: 5 trials/object x 10 unseen objects, compared against DexDiffuser's re-trained "DexSampler" module (DexEvaluator omitted). Results (Fig./table in Sec. VI): DexSampler baseline mean 58% (per-object 2/5–5/5 across 10 objects)
  - Ours (DexSimple) mean 96% (4/5–5/5 on all 10 objects, 9 of 10 objects at 5/5).

## Limitations stated by the authors
Open-loop deployment (key-frame generation only) is prone to sim-to-real gap and control/observation error; still relies on the simulator to filter successful data during the iterative pipeline, and that simulation remains time-consuming; the method is validated only in single-object scenes — multi-object scenes would likely need a stronger vision backbone (Sec. VII).

- "our dataset offers 700× more demonstrations" [than DexGraspNet, similar object-set scale] (Sec. I).
- "we achieve a 22% performance improvement over previous best methods on grasp synthesis tasks, setting a new benchmark in dexterous manipulation" (Sec. I) — see ambiguity note above (percentage-point gap, not relative %).
- "removing L_sdf causes a drastic drop in success rate from 63.7 to 0.7" (Sec. V-D).
- "the performance degradation ratio increases as data is reduced, illustrating that the success rates of the proposed DexSimple consistently improve with more training data" (Sec. V-C).

## Notes for the survey (which sections this feeds; contradictions with other notes)
Feeds "synthetic/optimization-seeded data scaling" — the counterpart to dexwild_2025's real-human-data scaling and dexumi_2025's exoskeleton scaling; Dex1B's data is entirely synthetic robot-hand poses generated by optimization + CVAE, never human motion, so it cannot be cross-cited as "human data scaling." Its scaling curve (Fig. 8) is qualitative only in the parsed text (no numeric table), weaker evidence than dexwild_2025's numeric scaling curve (28.7%→67.8%) — note this when comparing "scaling result" strength across the corpus. The explicit SDF-sphere penetration loss (L_sdf) and its ablation (63.7%→0.7% SR when removed) is a rare case in this batch where a paper directly reports a penetration-handling term's causal effect on success rate — useful for the "contact/penetration handling" comparison table alongside dextrack_2025 and other RL papers already in the corpus. Real-robot eval is open-loop (single predicted grasp pose + motion planning), not a closed-loop policy — weaker real-robot evidence than dexumi_2025 or teledexter_2026's closed-loop BC policies; flag this when the survey ranks "real-robot validation strength."
