# Tables: contents and the rows they are built from

Every table is generated by a script in tools/ from corpus/rows/*.json, so a table cannot
contain a value that no note confirmed. Cells that are null print as an em space, and each
table carries a line saying how many of its cells are empty, because the emptiness is part of
the finding.

Table 1. Task families against the properties that define success.
  Hand-written, not generated. Columns: what is held, what moves, what gravity does, what
  counts as failure, the shortest honest success criterion.

Table 2. Robot hands. From rows with class "hand".
  maker, country, DoF, actuated DoF, actuation, weight, fingertip force, tactile, price,
  open hardware, release status, source quality, corpus papers using it.
  Sorted by release status then DoF. Source quality is the column reviewers should read first.

Table 3. Announced and unreleased hands, separated out of Table 2.
  Same columns plus the date of the claim and whether it is datasheet, video or press.

Table 4. Simulators and physics engines. From rows with class "simulator".
  engine, contact model, solver, iterations, differentiable, GPU, default timestep, penetration
  exposed, throughput with hardware and env count, hands shipped, licence.

Table 5. Reward terms across in-hand reorientation papers.
  Rows are papers, columns are the recurring term families (pose tracking, object velocity,
  finger-object distance, action rate, torque or energy, drop or failure, contact or force,
  success bonus). A cell says whether the term is present in the paper, in the code, or in both.
  The mismatch column is the point.

Table 6. Teleoperation and human-data systems.
  system, operator interface, robot hand, retargeting objective in one clause, latency, rig cost,
  data collected, what the data was used for.

Table 7. The master method table. From rows with class "method".
  key, year, task family, paradigm, algorithm, hand and DoF, bimanual, simulator, real robot,
  real trials, unseen-object generalisation, penetration handling, code released.
  This is the table a reader scans to find comparable work; it is long and that is correct.

Table 8. The proposed evaluation protocol.
  axis, what is measured, how, minimum trial count, what is reported alongside it, why.

Table 9. The empty results matrix.
  Methods down the side, the Table 8 axes across the top, all cells empty. The survey does not
  fill it; it exists so that the next paper can.

Table 10. Existing surveys and what each covers.
  survey, year, scope, taxonomy used, bimanual covered, hardware covered, evaluation covered,
  gaps it names. Positions this survey against its predecessors.
